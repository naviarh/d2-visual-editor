# AGENTS.md — инструкции для ИИ-агентов, работающих с этим проектом

Проект: **D2 visual editor** — двусторонний редактор «код D2 ↔ визуальная схема».
Читайте этот файл полностью перед изменениями. Детали архитектуры — в `docs/architecture.md`, как разрабатывать и тестировать — в `docs/development.md`, исходный план — в `docs/plans/d2-editor-sync.md`.

## 1. Что это и как устроено (кратко)

- `index.html` — весь UI (тулбар, текстовый редактор слева, интерактивная схема на @xyflow/system справа). Инлайн-скрипт — современный JS (const/arrow/template). Открывается как `file://` (без сборки); `@xyflow/system` грузится с CDN — нужен интернет.
- `js/*.js` — логика графа, вынесена в **ES5 UMD-модули** (браузер + CommonJS). Не используют DOM.
- **Граф — источник истины** для хранения и структуры. **D2-текст — проекция графа** (два сериализатора: чистый и аннотированный). Правки текста сливаются в граф через merge-слой, который переносит позиции.
- Хранилище: `localStorage["d2editor:v1"]` (payload `v:1`, legacy-совместимо). **Не переименовывайте ключ** без миграции. UI-предпочтения — отдельно, `localStorage["d2editor:ui:v1"]` (`{codeWidth, exportName}` — ширина панели кода и запомненное имя файла экспорта).
- UI: панель «Код D2» — textarea + split-button «Копировать» с меню по шеврону (`#copy-menu`, `data-act`): `paste`/`replace`/`import`/`export`, затем `export-svg` (реализован), `export-drawio`/`export-mermaid`/`import-mermaid` (стабы «в разработке»). Панель «Схема» (@xyflow/system): + Блок, Стрелка, Группировать, селект формы (`#shapeSel`) для выбранного блока, Упорядочить по связям, +/−, Fit; pan/zoom, drag блоков, dblclick-rename через собственный модальный диалог.
- Тесты: `node:test`, 171 зелёных (`npm test`), E2E на puppeteer-core — 16 сценариев (`npm run test:ui`).

## 2. Карта модулей

| Файл | Глобал (UI) | Что делает | Ключевой API |
|---|---|---|---|
| `js/d2-serialize.js` | `D2S = window.d2mod` | Граф → D2-текст | `serializeClean`, `serializeAnnotated`, `stripMarkers`, `d2Key`, `treeOrder`, `defaultOrder` |
| `js/d2-parse.js` | `D2P = window.d2parse` | D2-текст → граф | `parseD2` (→ `{ok, graph}` или `{ok:false, error:{line,col,message}}`), `tokenize` |
| `js/d2-merge.js` | `D2M = window.d2merge` | Слияние распарсенного графа с текущим, перенос позиций | `mergeGraph(parsed, current, {selectedId, selectedEdgeId})` → `{graph, added, removed, selectedId, selectedEdgeId}` |
| `js/d2-layout.js` | `D2L = window.d2layout` | Авто-расстановка новых нод | `placeNewNode(graph, nodeId, {center})`; константы `PAD/HEAD/GAP/MARGIN/STEP` |
| `js/d2-sort.js` | `D2SORT = window.d2sort` | Упорядочение блоков по стрелкам | `sortByArrows(graph)` → новый граф (не мутирует вход) |
| `js/d2-shapes.js` | `D2SHP = window.d2shapes` | Реестр 18 форм: геометрия, контур, анкоровка | `renderShape(name, box)` → SVG-пути; `outlinePoints(name, box)` → полигон; `outlineIntersect(points, cx, cy, dx, dy)` → точка на контуре; `normalizeRatio(name, w, h)` → 1:1 для `circle`/`square`; `SHAPE_NAMES` |

UMD-паттерн в конце каждого модуля:
```js
if (typeof module !== "undefined" && module.exports) module.exports = api;
global.d2mod = api;
```
В тестах модули грузятся как CommonJS через `createRequire(import.meta.url).require("../js/x.js")`.

## 3. Критичные инварианты (не нарушать)

1. **`order` — единственный порядок эмиссии**: массив из id нод и рёбер вперемешку (как в тексте). `treeOrder()` даёт только ноды (pre-order). Новая нода/ребро добавляются в конец `order`. Позицию элемента в коде меняет только парсер (из текста) или явная команда (`sortByArrows`).
2. **`hasPos`** — «позиция зафиксирована». `placeNewNode` не трогает ноды с `hasPos:true`. Позиция «коммитится» установкой `hasPos=true`.
3. **Маркер `# @d2pos x,y`** — зарезервированный служебный формат (локальные координаты, целые). Пишется в конец строки после инлайн-комментария: `Client # note # @d2pos 60,300`. Разбирается `POS_RE` (якорь конца строки). Пользовательский комментарий, заканчивающийся этим паттерном, будет трактоваться как позиционный.
4. **Паритет представлений**: аннотированный = чистый + маркеры. `stripMarkers(serializeAnnotated(g))` = `serializeClean(g)`. Проверяется тестами, в т.ч. через `d2` CLI.
5. **Правило приоритета позиций** (правка текста): маркер в тексте авторитетен → иначе merge-эвристики из текущего графа → иначе авто-расстановка.
6. **Не переписывайте textarea во время ввода пользователя** (ломается каретка). Переписывать только при структурном изменении (added/removed) после debounce, при «чистой» перегенерации (`queueGen`) и в явных командах (toggle/sort).
7. **Модель — плоская по id**: id ноды = локальный D2-ключ и глобальная идентичность одновременно. Два узла с одинаковым id в разных скоупах (как `a.x -> b.x`) не представимы — парсер возвращает ошибку «дубликат имени узла», а не создаёт битый граф. Путь внутри скоупа, повторяющий id своего же предка (`"Группа 1".789` внутри `"Группа 1"`), резолвится в существующего предка (без дублей и циклов). Никакая функция не должна зацикливаться на битом графе: `absPos`/`isDescendant` — guard на 100 итераций, `treeOrder`/`boxSize` — guard `visiting` (и в `index.html`, и в `js/*`).

## 4. D2-семантика, которую обязан знать каждый агент

Сверена с реальным CLI `d2` v0.7.1:

- **Пробелы в незакавыченных ключах/метках не разделители.** `a b c` — одна нода с id `"a b c"`; `x: hello world` — метка `"hello world"`. **Явного «label-шортката» в D2 нет**.
- **Комментарии в d2 — только `#` и `"""…"""`**; `//` комментарием НЕ является (это часть unquoted-строки: `// header` — нода, `Client // note` — ключ `Client // note`). Соседние `#`-строки склеиваются в один комментарий через `\n`, пустая строка разделяет (d2 `parseComment`); инлайн-`#` после оператора прикрепляется к своему элементу и со следующей строкой не склеивается.
- **Блочные строки `|…|`** (этап C): `|` + символы-кавычки (не `[a-zA-Z0-9_]` и не пробел; включая `-`, `.`, `:`, `#`, сам `|` — так `|--|` даёт кавычку `--|`) + тег `[a-zA-Z0-9_.-]` (дефолт `md`; `| foo` → тег `md`, контент sameLine `foo`). Закрытие: последний символ кавычки + остаток кавычки + `|` (пустая кавычка → любой `|`). Контент — `trimSpaceAfterLastNewline` + `trimCommonIndent`; контент на строке открытия (`sameLine`) неявно получает отступ 2·глубина. Значение ноды/ребра и `label:` → `label` + `labelBlock = {tag, quote, value}`; прочие атрибуты (`tooltip`, `width`, `style`, `icon`; `shape` — нет) → `rawAttrs` в форме `key: |quote tag\n  <строки>\n<closer>`. `# @d2pos` на строке открытия — контент, на строке закрытия — комментарий-позиция (маркер аннотированной формы ставится на закрытие). При пустой кавычке первый `|` в контенте закрывает блок (ограничение d2). Незакрытая → ошибка «незакрытая блочная строка (ожидается …)».
- Маркер на строке один: от первого `#` до конца строки.
- **`$`/`*`/`...@` (этап D)** — распознаются, но не поддерживаются → явная ошибка с номером строки (детекция в токенизаторе на сырых символах, до `decodeEscape`): `$` в значениях и `"…"` → «подстановки ($) не поддерживаются», `$` в начале ключа → «переменные ($) не поддерживаются», `*` в ключе → «globs (*) не поддерживаются», `...@` в начале токена → «import spread (…) не поддерживается». Литералы: `\$`, одинарные кавычки, `*` в значениях, содержимое блок-строк, `...` в значениях, `$`/`*` в середине ключа (`a$b` — обычное имя). Стрелки `-*`/`*-` — нормальные рёбра. Сериализатор экранирует `$` в `"…"` (`d2Escape`).
- **Эмиссия значений (этап E):** метки нод/рёбер выводятся через `d2Value` — unquoted, когда безопасно (`unquotedSafeValue`: непусто, без ведущих/хвостовых пробелов, первый символ не `"`/`'`/`|`/`$`/пробел, не префикс `...@`, внутри нет `\r\n; # { } [ ]`, `$` и `\\`), иначе `"…"` с `d2Escape` (набор D2: `\ " $ \b \t \n \v \f \r`; `#` в кавычках не экранируется). **Ключи — консервативно** (`d2Key`: `[A-Za-z0-9_]+` или `"…"`): `d2 fmt` не трогает уже закавыченные ключи. Многострочная метка без `labelBlock` синтезируется в блок `|-md`. `$` в значении не представим в D2 — парсер отвечает ошибкой, round-trip не гарантируется.
- Ключ с точкой в кавычках (`"b.c"`) — литерал; приоритет самого длинного ключа над путём.
- **Формы (`shape: <имя>`):** 18 форм (`SHAPE_NAMES` в `d2-shapes.js`). Поле ноды `shape` присутствует только когда `shape:` написан явно, регистр сохраняется (registry ищет по нижнему регистру); вне скоупа `{…}` `shape:` — обычная нода; `shape` на ребре и значения-массивы/блок-строки (`shape: [a]`, `shape: |md …|`) остаются в `rawAttrs` lossless (d2 игнорирует их в рендере). Неизвестное имя (`shape: foo`) — валидно (`d2 validate`), сохраняется в поле и тексте, рендер показывает fallback-прямоугольник (скруглённый rx=8). `circle`/`square` — 1:1 (нормализация `normalizeRatio` по максимуму w/h в UI-пути `boxSize` и в анкоровке). Рёбра анкорятся к контуру формы: `edgeGeometry` → `outlinePoints` + `outlineIntersect` (ближайший выход луча центр→центр; для вогнутых форм — первое пересечение); контейнеры — прежняя прямоугольная рамка. `c4-person`: голова перекрывает верх тела (параметр `headOverlap`, голова рисуется поверх), контур — внешняя граница объединения без дублирующих/внутренних сегментов (дуга головы + периметр тела без перекрытого участка кромки). Остриё маркера стрелки стоит точно на контуре (`refX=10`). Метки `person`/`c4-person` — снизу (`shapeLabelBottom` в `index.html`, класс `.nlabel.bottom`). Рендер и экспорт используют одну `renderShape` из реестра; геометрия живёт в `params` записи (render/outline читают один `params`).
- Резервные атрибуты (`label, shape, style, width, ...` — см. `RESERVED` в `d2-parse.js`) становятся полями/`rawAttrs`; неизвестные — вложенными нодами (такова D2-семантика `a: { b: x }`).
- Ребро к необъявленной ноде (`a -> b`) создаёт неявную ноду `b` (`implicit: true`); позднее явное объявление сливается по id.
- Не поддерживается (сознательно): классы/`@`-директивы, импорты, переменные/подстановки `$`, `style`-грамматика, `near`, HTML-метки. Встречается → `rawAttrs` либо ошибка с номером строки, но не молчаливый сброс. **Массивы** (`x: [a, b]`, `a -> b: [x]`) распознаются и сохраняются без потерь как `valueArray` (нода/ребро), метка при этом остаётся пустой (id) — так же, как у d2; `x: [a] { b }` — ошибка «массив не может иметь тело '{}'» (паритет с CLI).

## 5. Пайплайн правки текста (не разрывать)

`input` → debounce **3 c** (`TEXT_EDIT_MS`) → `onTextEdit`:
1. `parseD2(out.value)`; ошибка → статус «Ошибка D2: строка N — …», граф и текст **не трогаются**.
2. `mergeGraph(parsed, currentGraph(), {selectedId, selectedEdgeId})`.
3. Для `added` — `placeNewNode(merged.graph, id, {center: centerFlow()})`.
4. `applyGraph` → обновить selection → `renderEdges()/renderNodes()/renderHint()` → `queueSave()`.
5. `added||removed` → `regenerateTextView()` + статус «Новых блоков: N (авто-позиция)»; иначе `lastGraphText = out.value` + «Синхронизировано».

Мутации схемы (drag, добавить блок, стрелка, группа, delete, rename): `render()` → `queueSave()` (400 мс) + `queueGen()` (1 c). `queueGen` переписывает textarea **только если** `out.value === lastGraphText` (чистый).

Toggle «Скрыть/Показать позиции»: переписывает textarea только если он чист; иначе лишь переключает `showComments` (применится при следующем успешном merge).

## 6. Merge-эвристики идентичности (§5 плана)

- Сначала точный матч по полному пути `a.b.c`.
- Затем эвристики для несовпавших: `candidateScore` ≥ **3**: маркер на той же позиции +3, label +2, тот же родитель +1, общие соседи по label +2 (макс +4).
- Переименованный контейнер распространяет новое имя на потомков (`a.b → x.b`).
- Рёбра матчатся по паре (source,target) уже на новых id, приоритет совпадению label (смена подписи сохраняет id). Новые рёбра получают распарсенный id, если свободен, иначе `eN`.
- Следствие (не баг): правка имени при том же маркере позиции считается переименованием, а не добавлением.

## 7. Авто-расстановка и сортировка

- `placeNewNode`: якорь — сосед по ребру (`source` новой стрелки слева от цели, `target` — справа, `GAP=32`) → родитель-контейнер (`PAD/HEAD` 24/28, только вправо/вниз) → центр вьюпорта; свободное место ищется спиралью (`STEP=40`, `MARGIN=8`, лимит 2000).
- `sortByArrows`: DFS pre-order по скоупам; входящие стрелки считаются **внутри скоупа** (прямые дети контейнера / корни верхнего уровня), не глобально; цели-контейнеры и вложенные цели — в отложенный список; циклы защищены `visited`; детерминизм от порядка рёбер. Возвращает **новый** граф, вход не мутирует.

## 9. Стиль и правила работы

- `js/*.js`: ES5 в UMD-IIFE, `var`, 2 пробела, точки с запятой, `single quotes`, **без DOM**. Чистые функции над v2-графом.
- `index.html` (инлайн): современный JS, 2 пробела, `single quotes`.
- Строки интерфейса и статусы — на русском («Синхронизировано», «Ошибка D2: строка N — …», «Новых блоков: N (авто-позиция)»).
- Комментарии в коде — только по запросу пользователя (в проекте есть поясняющие, не удаляйте их без нужды).
- Не добавляйте неявные `npm`/бинарные зависимости в рантайм UI: приложение открывается с `file://` и не собирается.
- Храните графовые операции чистыми и покрытыми юнит-тестами; UI — тонкой обвязкой в `index.html`.
- Перед изменениями смотрите `docs/architecture.md` и `docs/plans/d2-editor-sync.md`; после — гоняйте `npm test` (+ `npm run test:ui`).
- Ветки/коммиты: работа ведётся на `feature/*`, основной — `main`. Коммитить и сливать ветки — только по явной просьбе пользователя.
