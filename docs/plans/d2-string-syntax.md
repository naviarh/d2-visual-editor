# План: синтаксис строк D2 — приведение к стандарту

Статус: **завершён** — все этапы A–F реализованы (см. раздел 6).
Эталон: официальный парсер `d2parser/parse.go` (master, ~v2.x) и CLI **d2 v0.7.1**, установленный локально (`/home/i/.local/bin/d2`). Все правила ниже сверены с реальным CLI (см. раздел 8).

## 1. Цель и границы

**Цель.** Текстовый редактор (панель «Код D2» + пайплайн `d2-parse.js`/`d2-serialize.js`) должен принимать и корректно интерпретировать **все валидные формы строк D2** и отклонять невалидные с точной ошибкой (строка/колонка) — так же, как это делает d2 v0.7.1. Речь только о **синтаксисе написания кода**, а не о функциональности.

**Вне скоупа (функциональность, НЕ реализуем).** Рендеринг markdown/кода/LaTeX из блочных строк; вычисление переменных и подстановок `$var`/`${...}`; globs/import-паттерны (`*`, `&`, `...@`, `..$`); autoformat отступов блочных строк; стили/директивы. Для таких конструкций синтаксис должен **распознаваться**, а содержимое либо сохраняться без потерь в `rawAttrs`, либо давать явную ошибку «не поддерживается» с номером строки — но никогда не превращаться молча в другое значение (это уже зафиксировано в AGENTS.md §4).

**Критерий приёмки.** Для каждого случая из таблицы раздела 8 результат проекта совпадает с d2 v0.7.1 (метка/id/структура при успехе, ошибка с той же строкой при отказе). Дополнительно — `d2 validate` и round-trip `parse→serialize→parse`.

## 2. Эталон: строки D2 v0.7.1 (сверено с CLI)

### 2.1 Комментарии

- `# …` — комментарий до конца строки. Если следующая строка снова начинается с `#` (между ними ровно одна пустая/переводная строка) — это **продолжение того же** комментария (в d2parser `parseComment`).
- `""" … """` — блочный комментарий (может быть многострочным; общий отступ строк убирается). Открытие/закрытие строго `"""`, внутри можно всё, кроме незакрытой `"""`.
- **`//` — НЕ комментарий.** Это просто текст незакавычённой строки. Проверено CLI: `// header` → нода с label `// header`; `x -> y // note` → ребро в ноду `y // note`.

### 2.2 Незакавычённые строки (`parseUnquotedString`)

- Пробелы — **не разделители**; лидирующие/хвостовые пробелы обрезаются (внутренние сохраняются).
- **Терминаторы везде:** `\n`, `;`, `#`, `{`, `}`, `[`, `]`.
- **Дополнительно в ключе:** `:`, `.`, `<`, `>`, `&`; а также `-` перед `-`/`>`/`*` (рёберные маркеры `--`, `->`, `-*`).
- **Разрешены внутри строки (проверено CLI):** `"`, `'`, `(`, `)`, `,`, `/`, и в значениях `:`, `.`, `<`, `>`.
  - `x: don't` → label `don't`
  - `x: a"b` → label `a"b`
  - `x: (a)` → label `(a)`
  - `x: a.b` / `x: a,b` / `x: a:b` → label целиком
- **`*`** — элемент glob-паттерна (паттерны не поддерживаем → см. §4).
- **`$`** (в значениях) — начало подстановки `$var`/`${...}` (не поддерживаем → §4).
- **`\`** — escape: `\a \b \f \n \r \t \v \\ \"`; **неизвестный escape отбрасывает `\`** (`"\q"` → `q`); `\` + перевод строки — перенос строки (продолжение).
- Не может начинаться с `...@` (import spread) → ошибка.

### 2.3 Двойные кавычки (`parseDoubleQuotedString`)

- Экранируются: `\a \b \f \n \r \t \v \\ \"` (тот же `decodeEscape`). Неизвестный escape — `\` отбрасывается (`"a\qb"` → `aqb`).
- `\` + перевод строки — перенос строки.
- **Неэкранированный перевод строки или конец файла без закрывающей `"` → ошибка** «double quoted strings must be terminated with "».
- `$` в значении — подстановка (как §2.2).

### 2.4 Одинарные кавычки (`parseSingleQuotedString`)

- **Единственный escape: `''` → `'`** (`'it''s'` → `it's`).
- Обратный слеш **не экранирует**: `'a\nb'` → литерал `a\nb`; `'a\'b'` — **ошибка** (незакрытая строка).
- Исключение: `\` + перевод строки — перенос строки.
- Неэкранированный перевод строки или конец файла без `'` → ошибка.

### 2.5 Блочные строки (`parseBlockString`)

- Открываются `|`, за которым идут **символы-кавычки** (любые не-алфавитно-цифровые, не пробел, не `_`; например `|`, `||`, `|---|`, а также `-`, `.`, `:`, `#`, `|` — проверено CLI: `|--|` → кавычка `--|`, `|-md` → кавычка `-`, `|:a` → кавычка `:`) и затем **тег** (`[a-zA-Z0-9_.-]`, стоп на пробеле и любом другом символе; по умолчанию `md`; `| foo` → тег `md` + контент sameLine `foo`, `|md foo` → тег `md` + контент sameLine `foo`).
- Закрытие — **последний символ кавычки + остаток кавычки + `|`** (например, для `|…|` закрытие `|`, для `||…||` закрытие `||`, для `|--|` закрытие `|-||`, для `|++…|` закрытие `++|`). При пустой кавычке закрывает любой `|`.
- После тега пробелы/табы пропускаются: следующий символ на той же строке → контент начинается там же (`sameLine`, неявный отступ `getIndent()` = 2·глубина); перевод строки → контент со следующей строки.
- К содержимому применяется `trimSpaceAfterLastNewline` + `trimCommonIndent` (убирается общий отступ; первая строка с текстом неявно получает текущий отступ).
- Внутри можно всё: `#`, `//`, кавычки, `"""`, переводы строк, сам символ `|` — если кавычка не пустая (`|++`…`++|` позволяет `|` внутри). Пример из CLI: `x: |md` + строки + `|` парсится без ошибок.
- Ограничение d2 (воспроизводим, не чиним): при пустой кавычке первый же `|` в контенте закрывает блок (например, markdown-таблицы `| a |` обрываются).
- `# --- @d2pos x,y` на строке открытия становится **контентом** (sameLine), а не комментарием — поэтому аннотированная форма ставит маркер на строку закрытия (`| # --- @d2pos x,y`), где он уже настоящий `#`-комментарий.
- Недостаточный отступ — не ошибка, autoformat «дополнит» (в нашем скоупе: просто принять).

### 2.6 Смежное, затрагиваемое токенизатором

- `;` — разделитель операторов (эквивалент перевода строки) — проект уже так делает.
- Рёбра: `->`, `<-`, `<->`, `--`, `-*`, `*-`. В v0.7.1 **нет** групп рёбер `(a, b) -> c` — это парсится как нода `(a, b)` (проверено CLI).

## 4. Поведение для неподдерживаемой функциональности

По конвенции проекта (AGENTS.md §4): «Встречается → `rawAttrs` либо ошибка с номером строки, но не молчаливый сброс».

- **Блочная строка**: значение ноды/ребра и атрибут `label` → `label` = значение + `labelBlock = {tag, quote, value}` (свойство ноды/ребра); блок у прочего атрибута (например `tooltip`, `width`, `style`, `icon`; `shape` блок-строку НЕ принимает — проверено CLI) → `rawAttrs` в форме `key: |quote tag\n  <строки>\n<closer>` (как уже делается для `style: {…}`, `parseAttrBody`). Round-trip без потерь.
- **`$`-подстановки**: если встретились в ключе/значении — либо `rawAttrs` (пассивный режим), либо ошибка «подстановки ($) не поддерживаются» со строкой. Рекомендация: ошибка по умолчанию (как уже сделано для `@`-директив: `errorAt(t, "директивы/переменные (@) не поддерживаются")` в `d2-parse.js:536`).
- **Globs `*` / import spread `...@`**: ошибка «globs не поддерживаются» / «import spread не поддерживается». `...@` в начале unquoted — в любом случае ошибка (по D2).
- **Блок-комментарий `"""…"""`**: поддержать как комментарий (это синтаксис, не функциональность) — комментарии уже хранятся (`headerComments`/`comments`/`trailingComment`).

## 5. Изменения по файлам

### `js/d2-parse.js`

1. **Лексер строк по контексту.** Текущий `tokenize()` — отдельный проход без знания «ключ это или значение», а у D2 терминаторы зависят от контекста (`inKey`). Рекомендация: следовать d2parser — вынести сканирование строк в функции уровня парсера `parseString(inKey)`/`parseUnquotedString(inKey)`/`parseDoubleQuotedString`/`parseSingleQuotedString`/`parseBlockString`, токенизировать «сырые» прогоны, а терминацию определять в парсере. Это крупный, но локализованный рефакторинг раздела «строки».
2. **`decodeEscape` по D2:** `a b f n r t v \\ "`; неизвестный → вернуть символ без `\`. Применить к незакавычённым и двойным кавычкам.
3. **Перенос строки:** `\` + `\n` = продолжение строки (в unquoted, одинарных, двойных).
4. **Одинарные кавычки:** новый токен; `''` → `'`; `\` не экранирует (кроме `\`+`\n`); незакрытая → ошибка.
5. **Блочные строки** (✅ этап C): в токенизаторе ветка `inValue && ch === "|"` — сканирование кавычки-символов (`blockQuoteEndsAt`), тега (`blockTagEndsAt` = `[a-zA-Z0-9_.-]`, дефолт `md`), пропуск пробелов, `sameLine`-флаг, контент до закрытия `blockStringCloser(quote)` (последний символ кавычки + остаток + `|`; при пустой кавычке — любой `|`). Токен `{type:"block", tag, quote, content, sameLine}`; незакрытая → ошибка «незакрытая блочная строка (ожидается …)»; `inValue=false`. В парсере `blockValue(t)` = `trimCommonIndent(trimSpaceAfterLastNewline(content))` с неявным отступом `"  ".repeat(curDepth()*2)` для `sameLine`; `parseValue` возвращает токен с `.value`; значение ноды/ребра и `label:` → `label` + `labelBlock`; прочие атрибуты → `rawAttrs`-форма блок-строки.
6. **Комментарии:** убрать ветку `//`; `#`-комментарий с поддержкой «продолжения»; добавить `"""…"""`.
7. **`;`** — оставить как разделитель (уже есть).
8. **Ошибки:** `...@` в начале unquoted; `$`/`*` → «не поддерживается» (или `rawAttrs`); неподдерживаемые escape-последовательности НЕ считаются ошибкой (по D2 `\` просто отбрасывается).
9. Сохранить `POS_RE`-маркеры и merge-слой нетронутыми — они работают поверх уже распарсенных строк.
10. **`$`/`*`/`...@` (✅ этап D):** детекция в токенизаторе на сырых символах (до `decodeEscape` — иначе `\$` неотличим от `$`). В `tokenize()`: top-of-loop `src.startsWith("...@", i)` → ошибка «import spread (…) не поддерживается»; в word-run после escape-ветки — `$` при `inValue || buf пуст || след. символ '{'` → «подстановки ($) не поддерживаются» (старт ключа → «переменные ($) не поддерживаются»), `*` при `!inValue` → «globs (*) не поддерживаются» (в значениях `*` — литерал; `-*`/`*-` ловятся `arrowLen` раньше); в двойных кавычках `$` → «подстановки ($) не поддерживаются». Одинарные кавычки, блок-строки, `\$` — литерал. Колонка ошибки = позиция токена (сверена: `x: $var` 1:4, `x: 5$foo` 1:5, `x: "a$b"` 1:6, `x: ...@y` 1:4 — совпадает с d2).

### `js/d2-serialize.js`

1. `d2Key`/эмиссия значений: набор экранирований по D2 (`\` и `"`, при необходимости `\n` и др.); опционально — выбор кавычек по содержимому (unquoted, когда безопасно по терминаторам §2.2, иначе `"…"`, для значений с `\n` — одиночные кавычки или блочная строка). **Этап D:** в `d2Key` добавлено `\$`-экранирование (`$` в `"…"` — подстановка в d2; `"\$"` → литерал), поэтому значения `a$b`/`5$foo` из quoted-источников проходят round-trip и компилируются в d2.
2. Гарантировать, что блок-строки из `rawAttrs` выводятся как есть (без переквотирования).
3. **Блок-строки (✅ этап C):** `emitBlockString(lines, openerLine, block)` — строка открытия `|quote tag`, строки контента с отступом `ws + "  "`, строка закрытия; возвращает индекс строки закрытия для суффикса. В `emitNode`: контейнер → блок как проп `label:`; иначе блок-значение ноды `key: |…|` (суффикс маркера на строке закрытия); в `emitEdge`: `ed.labelBlock` → `src -> tgt: |…|` (trailingComment на строке закрытия). Равномерный +2-отступ контента стабилен под `trimCommonIndent` (round-trip).
4. **Эмиссия значений (✅ этап E):** `d2Value(s)` — unquoted, когда `unquotedSafeValue` (непусто, без ведущих/хвостовых пробелов, первый символ не `"`/`'`/`|`/`$`/пробел, не префикс `...@`, внутри нет терминаторов `§2.2` (`\r\n; # { } [ ]`), `$` и `\\`); иначе `"…"` через `d2Escape` (полный escape-набор D2: `\ " $ \b \t \n \v \f \r`; `#` внутри кавычек не экранируется). Ключи остаются консервативными (`d2Key`: `[A-Za-z0-9_]+` или `"…"`) — `d2 fmt` сохраняет их кавычки; метки нод/рёбер эмиттятся через `d2Value`. Многострочная метка без `labelBlock` синтезируется в блок `|-md` на лету (этап C). `$` в значениях не представим в D2 — парсер даёт «подстановки ($) не поддерживаются» (этап D), сериализатор эмиттит `"\$"`, но round-trip не гарантируется (осознанное ограничение).
5. Не ломать `stripMarkers`/паритет clean↔annotated (инвариант №4).

| **F** | CLI-паритет: прогон таблицы §8 на `d2 validate`/`d2 fmt`; обновить документацию; полный `npm test` + `npm run test:ui`. | 100% зелёные, таблица §8 совпадает |

**Статус:** этапы **A** ✅ (`feat(parse): context-aware D2 string lexer`), **B** ✅ (`feat(parse): D2 comments parity`), **C** ✅ (блочные строки `|…|`), **D** ✅ (`$`/`*`/`...@`: явные ошибки), **E** ✅ (`d2Value`/`d2Escape`: unquoted-when-safe эмиссия значений), **F** ✅ (`test/cli-parity.test.mjs`: вся таблица §8 прогоняется на `d2 validate`, вердикты и строки ошибок совпадают, метки сверены с `d2`-рендером; массивы-значения `x: [a]` — `valueArray`, не метка).

**Риски.**
- Пункт 2 (убрать `//`-комментарии) — **ломающее изменение**: существующие файлы пользователя, где `//` использовался как комментарий, начнут трактовать `//` как часть имени. Отметить в чеклисте: после этапа B вручную проверить сохранённые демо. Альтернатива (отклонена): оставить `//` комментариями в обход стандарта — противоречит цели.
- Пункт 7 (контекстный лексер) — самый объёмный; возможны регрессии в merge. Митигация: строго поэтапные PR + таблица паритета до реализации.
- `d2 v0.7.1` устарел относительно master (`//` отсутствует в обеих версиях; `#` и `"""` присутствуют). Сверка — по установленному CLI и по master-исходнику (совпадают по строкам).

## 7. Связь с существующими инвариантами

- **Инвариант №3 (маркер `# --- @d2pos x,y`)** — не нарушается: в терминах D2 это обычный `#`-комментарий в конце строки. После этапа B важно, чтобы «продолжение комментария» не «съедало» маркер следующей строки — в нашей аннотированной генерации маркер всегда на отдельной строке, риск минимален, но проверить.
- **Инвариант №4 (паритет clean/annotated)** — проверяется после этапа E.
- **Инвариант №1 (`order`)** — не затрагивается.
- **Инвариант №5 (приоритет позиций)** — не затрагивается.

## 8. Таблица паритета (вход → ожидание) — сверено с CLI v0.7.1

| Вход | Ожидание (как в d2 v0.7.1) |

| `x: a"b` | label `a"b` |

| `x: [a]` | атрибут-массив |

| `x: 'it''s'` | label `it's` |
| `x: 'a\nb'` | label `a\nb` (литерал, без интерпретации) |

| `x: "a\qb"` | label `aqb` |
