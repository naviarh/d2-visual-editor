# План: поддержка форм (shapes) блоков D2

Статус: **реализовано** — реестр 18 форм + fallback, анкоровка рёбер к контуру, интерактивный рендер (`#shapeSel`), экспорт SVG, CLI-паритет; этапы A–F завершены (см. §6).
Ветка: `feature/shapes`.
Эталон: официальный каталог форм d2 v0.7.1 (страница `d2lang.com/tour/shapes/`) и установленный CLI `/home/i/.local/bin/d2` — геометрия сверена с реальным SVG-рендером.

## 1. Цель и границы

**Цель.** Научить редактор понимать и визуально отображать все 18 форм блоков D2, с точной анкоровкой рёбер к контуру фигуры, с кастомизированной (отличающейся от стандарта) геометрией части форм и с возможностью безболезненно менять геометрию в дальнейшем.

**Вне скоупа (этап 1).** Специальные объекты D2 (`text`, `code`, `image`, `icon`, `sql_table`, `class`, `sequence_diagram`) — НЕ реализуем, но `shape: <такое имя>` должен не падать: рендер по fallback-правилу (§2.3), текст проходит round-trip. Геометрия контейнеров (скоупов) и типы окантовок (сплошная/двойная/пунктирная) — пока НЕ меняем, но архитектура обязана их предусматривать (§4.4). Ручной ресайз нод — пока НЕ добавляем, но архитектура должна позволять его добавить.

**Критерий приёмки.** Для каждого имени формы: известная форма рисуется корректной геометрией; `d2 validate`-поведение совпадает (неизвестное имя — валидно); рёбра крепятся к контуру (для вогнутых форм — к ближайшей точке выхода луча); изменение параметра геометрии одной формы не требует правок в анкоровке рёбер и других формах.

## 2. Эталон: shapes в d2 v0.7.1 (сверено с CLI)

### 2.1 Каталог (18 форм)

`rectangle` (дефолт), `square`, `page`, `parallelogram`, `document`, `cylinder`, `queue`, `package`, `step`, `callout`, `stored_data`, `person`, `diamond`, `oval`, `circle`, `hexagon`, `cloud`, `c4-person`.

### 2.2 Поведение имён (проверено CLI)

- **Регистронезависимо при рендере**: `shape: Diamond` рисуется как `diamond`.
- **`d2 fmt` сохраняет исходный регистр** (`shape: Diamond` не нормализуется). → модель хранит значение как в тексте, реестр ищет по нижнему регистру, сериализатор выводит исходную форму.
- **`d2 validate` не проверяет имена форм**: `shape: foo` — валидно.
- **`d2 render` падает**: `unknown shape "foo"` (строка:колонка атрибута).
- **`shape:` вне скоупа `{…}`** — это нода с именем `shape` (атрибут применяется только внутри контейнера). Текущее поведение нашего парсера уже такое (`js/d2-parse.js`, ветка `scopeNode && single && RESERVED[key]`).
- **`shape` на ребре** (`a -> b: { shape: diamond }`) — d2 принимает (validate и render проходят) и **игнорирует**: визуально ни на что не влияет. → храним в `rawAttrs` lossless, в поле не переводим.
- **`shape: [a, b]`** (массив) — validate проходит, render падает: `reserved field shape does not accept composite` (строка:колонка атрибута).
- **`shape: |md …|`** (блок-строка) — validate и render проходят, но d2 рисует ноду **вообще без фигуры** (плавающая метка; дефект d2 v0.7.1).

### 2.3 Наше правило для неизвестного и нестандартного значения

Парсер НЕ даёт ошибку (как `d2 validate`); рендер показывает **«слегка закруглённый прямоугольник»** (как текущий дефолт, `rx=8`), НЕ падая (в отличие от `d2 render`).

Единое правило для всех «не-имён-формы» значений: массив `shape: [a]`, блок-строка `shape: |md …|`, неизвестное имя `shape: foo` — **не попадают в поле `shape`** (в случае массива/блока остаются в `rawAttrs` lossless, чтобы текст прошёл round-trip), рендер показывает fallback-прямоугольник. Неизвестное *имя* сохраняется в поле и в тексте без искажения (чтобы `shape: foo` снова вывелось как `shape: foo`).

### 2.4 1:1-формы

`circle`, `square` сохраняют соотношение 1:1:
- длинная метка, раздувающая ширину → высота растёт вместе с шириной;
- явные `width`/`height` → обе стороны = максимуму из двух.

## 3. Кастомизация геометрии (зафиксированные решения)

Шесть форм делаем отличными от стандарта. Все величины — именованные параметры в реестре (числовые коэффициенты), чтобы менять их позже без правок логики:

| Форма | Стандарт (измерено на рендере d2 v0.7.1) | Кастомизация |
|---|---|---|
| `document` | нижняя грань — волна амплитудой ~±10px от базовой линии | **уменьшить амплитуду волны** (параметр `waveAmp`) |
| `cylinder` | эллипсы верха/низа выступают ~0.36 ширины | **сделать овалы уже** (параметр `ellipseRise`) |
| `queue` | боковые дуги-«пузыри» выступают ~24px с каждой стороны при корпусе ~58px | **сделать овалы уже** (параметр `bubbleRise`) |
| `callout` | треугольный хвост снизу: ширина 30, длина 45 (в измеренном масштабе) | **шире и короче** (параметры `tailW`, `tailH`) |
| `person` | голова r~10, плечи ~44×28 (относительно бокса) | **компактнее**: голова меньше, плечи уже (параметры `headR`, `bodyW`) |
| `c4-person` | закруглённый прямоугольник 56×62 + круг r~12 сверху | **круг меньше** (параметр `headR`) |

Остальные 12 форм — стандартная геометрия D2. При реализации точные коэффициенты подбираются на глаз от измеренных; анкоровка рёбер автоматически следует за геометрией (§4.3).

## 4. Архитектура

### 4.1 Реестр форм (data-driven)

Новый DOM-свободный модуль `js/d2-shapes.js` (ES5 UMD, как остальные `js/*`, тестируется через node:test). Каждая форма — запись реестра:

```js
SHAPES = {
  "diamond": {
    ratio: null,                       // null | 1 (1:1-формы)
    params: { ... },                   // именованные коэффициенты геометрии
    render: function (a, s, opts) {},  // → SVG-строка (интерактив и экспорт)
    outline: function (a, s) {}        // → [{x,y},…] замкнутый полигон контура
  },
  ...
}
```

- `params` — единственное место, где живут числа геометрии (амплитуды, выступы, радиусы, пропорции).
- `render` строит SVG из `params` + бокса `{x,y,w,h}`.
- `outline` строит полигон **из тех же `params`** (дуги/кривые аппроксимируются сегментами).
- Fallback-форма `rectangle` (слегка скруглённый) — запись по умолчанию для неизвестных имён.
- Добавить новую форму / изменить геометрию = правится одна запись; `render` и `outline` обновляются согласованно, потому что оба читают один `params`.

### 4.2 Модель

Нода получает поле `shape` (строка, значение как в тексте, регистр сохраняется). **Поле присутствует только когда `shape:` явно написан** (отсутствие = не эмитится; рендер трактует отсутствие/неизвестное имя как `rectangle` — fallback).

Парсер: в `parseAttrBody` ветка `key === "shape"` → только для **нод** (отличать по наличию `children`: у ноды есть, у ребра — нет), `target.shape = String(v.value)`. Значения-массивы и блок-строки (`shape: [a]`, `shape: |md …|`) в поле НЕ пишутся — остаются в `rawAttrs` (lossless, правило §2.3). `shape` на ребре — d2 игнорирует (§2.2), оставляем в `rawAttrs`.

Сериализатор: эмитит `shape: <raw>` из поля **сразу после `label`** (эмиссия label уже первая; `d2 fmt` атрибуты не переставляет, канонического порядка нет — наш единообразный порядок не конфликтует с паритетом).

### 4.3 Анкоровка рёбер к контуру

Требование: стрелки цепляются к точному контуру фигуры, и смена геометрии не должна ломать стыковку.

Замена функции `border` в `edgeGeometry` (`index.html:530`) на пересечение луча «центр→центр» с сегментами полигона `outline()` той же формы (ближайшая точка пересечения — точка выхода). Для вогнутых форм (queue, callout, step, package) луч пересекает контур несколько раз — берём первую (ближайшую) точку. Работает для любой формы, т.к. использует тот же `outline`, что и `render`.

### 4.4 Расширяемость контейнеров и окантовок

Контейнеры (скоупы) сейчас рисуются пунктирным прямоугольником — НЕ меняем. Но запись формы обязана предусматривать:
- **геометрию контейнера** (закруглённый прямоугольник, овал и др.) — поля `containerRender`/`containerOutline` либо `container`-флаг;
- **тип окантовки** (сплошная/двойная/пунктирная) — поле `borderStyle` в записи/опциях рендера (сейчас контейнер использует пунктир — это лишь `borderStyle` на будущее).

### 4.5 Размеры без ручного ресайза

Факт о текущем коде: размер ноды = её поля `.w`/`.h` (новые ноды — фиксированные 150×70, `index.html:837`); атрибуты `width`/`height` из D2-текста сейчас идут в `rawAttrs` и **на размер не влияют**; авто-подбора под метку нет. Для форм это менять не будем (заявлено вне скоупа), поэтому:

- `ratio: 1`-формы (`circle`/`square`) нормализуют стороны до максимума из текущих `.w`/`.h` — в UI-пути (`boxSize` в `index.html:405` либо внутри `render`/`outline` реестра);
- отдельное будущее решение — начать применять `width`/`height` из кода (сейчас игнорируются);
- архитектура реестра не мешает добавить ручной ресайз позже (render/outline параметризованы боксом).

### 4.6 UI

Тулбар: выпадающий список форм для выбранной ноды (+ быстрое «сбросить в rectangle»). Смена формы → мутация графа → `render()` + `queueGen()` (существующий пайплайн). Интерактивный рендер нод: внутри `<div class="node">` инлайн-`<svg>` с геометрией формы (CSS-обвязка div/выделение/drag остаются). Экспорт `buildSVG` — та же `render()` из реестра.

## 5. Изменения по файлам

### `js/d2-shapes.js` (новый)

- Реестр `SHAPES` (18 форм + fallback `rectangle`), `getShape(name)` (по нижнему регистру, fallback).
- `renderShape(name, a, s, opts)` → SVG-строка; `outlinePoints(name, a, s)` → полигон.
- `outlineIntersect(points, cx, cy, dx, dy)` → точка пересечения луча с полигоном.
- `normalizeRatio(name, w, h)` → `{w,h}` для 1:1.
- ES5 UMD, без DOM, чистые функции над боксами.

### `js/d2-parse.js`

- Поле ноды `shape` (только когда `shape:` написан явно; регистр сохраняется; вне скоупа `shape:` — нода). В `parseAttrBody`: `key === "shape"` → только для нод (наличие `children`), `target.shape = String(v.value)`; у рёбер и для массивов/блок-строк (`shape: [a]`, `shape: |md …|`) — оставить в `rawAttrs` (§4.2).

### `js/d2-serialize.js`

- Эмиссия `shape: <raw>` из поля сразу после `label`. Не дублировать из `rawAttrs`. `d2 fmt` атрибуты не переставляет — единообразный порядок не конфликтует с паритетом. Инвариант №4 (clean↔annotated) сохранить.

### `js/d2-layout.js` / `boxSize`

- `boxSize` существует в двух местах: `js/d2-layout.js:27` (для авто-расстановки, дефолты 150×70) и `index.html:405` (UI-путь, использует `.w`/`.h`). - **C** — самый рискованный: анкоровка к вогнутым контурам (queue/callout/step). Митигация: отдельный этап, таблица тестов пересечений.

## 7. Связь с инвариантами

- **№1 (`order`)** — не затрагивается.
