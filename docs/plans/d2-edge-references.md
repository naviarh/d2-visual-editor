# План: ссылки на соединения по индексу `(a -> b)[N]`, фикс точечных путей, паритет цепочек

Статус: **реализовано** (2026-08-10). Паритет проверен тестами, в т.ч. через CLI `d2` v0.7.1 (см. §11).
Эталон: установленный CLI `d2` v0.7.1 (`/home/i/.local/bin/d2`) — все утверждения ниже проверены на реальном рендере и `d2 fmt`; фикстуры в `/tmp/opencode/*.d2`.

## 1. Цель и границы

**Цель.** Поддержать стандарт D2 «ссылки на соединения по индексу» — `(a -> b)[0].label: hi`, `(a -> b)[*].style.stroke: red`, `(a -> b -> c)[0].field: v`, ссылки без индекса `(a -> b).field: v` — в текстовом редакторе (парсинг → свёртка в inline-атрибуты → каноническая сериализация). Параллельно починить пре-существующий баг точечных путей в attr-телах рёбер/нод и довести до паритета d2 семантику цепочек `a -> b -> c`. Визуальный редактор не меняется структурно (регрессий нет, см. §10).

**Вне скоупа.**
- Визуальное применение `style.*`/`width`/`tooltip`/`icon` (rawAttrs не рендерятся) — отдельный кандидат, см. `docs/plans/d2-visualization-coverage.md:268`.
- Ссылки на одиночный ключ `(a)`: в d2 нестабильны (голая `(a)`/`(a)[0]` компилируются в пустой no-op, `(a).label: x` — «map value without key») → даём чистую ошибку (§3.5).
- Globs в конечных точках `(a -> *)` (проект globs не поддерживает).
- **Сохранение формы цепочки** `a -> b -> c` при сериализации (решение пользователя от 2026-08-10): цепочки распадаются на отдельные записи `a -> b` + `b -> c` — семантика идентична (для d2 и для графа), сохранение формы требует тега цепочки в парсере, пропуска неявных нод с guard'ами и меняет порядок/тесты; отложено в отдельный кандидат.
- Root-стили, `near`, импорты, классы, переменные.

**Критерий приёмки.**
- Все проверенные d2-паритетные формы парсятся, сворачиваются и сериализуются; выводимый текст проходит `d2` compile и `d2 fmt`.
- Ссылка с явным индексом (`.field`/`: value` или голая) вне диапазона / на необъявленное соединение → ошибка парсера с номером строки (паритет «indexed edge does not exist»; голая ссылка с в-диапазона индексом — тихий no-op, проверено CLI 2026-08-10).
- Ссылка без индекса → **создаёт новое соединение** (как объявление `a -> b: {…}`), даже если совпадения уже есть; `[*]` без совпадений вовсе → тихий no-op (паритет d2, проверено).
- Модель не меняется: новых типов стейтментов нет; ссылка без индекса добавляет ребро в `order` (как объявление), индексные и `[*]` — свёртка в существующие; merge/позиции не затрагиваются.
- Round-trip: `(a -> b)[0].label: hi` → `a -> b {label: hi}` (канонический inline), содержимое сохраняется.
- Документ, изначально валидный для `d2`, после фикса точечных путей остаётся валидным (сейчас ломается).

## 2. Эталон: ссылки на соединения в d2 v0.7.1 (сверено с CLI)

### 2.1 Синтаксис и семантика

| Запись | Поведение d2 (проверено) |
|---|---|
| `(a -> b)[0].label: hi` | применяется к 0-му (по порядку объявления) соединению ключа `(a,b,->)`; override label |
| `(a -> b)[1]` при одном `a -> b` | ошибка компиляции `indexed edge does not exist` (с line:col) — **и при присваивании, и у голой ссылки** (проверено CLI 2026-08-10: `(a -> b)[5]` без присваивания → ошибка) |
| `(a -> b).label: hi` (без индекса) | **создаёт НОВОЕ соединение** `a -> b {label: hi}` — как объявление `a -> b: {label: hi}`; применяется только к нему, даже если совпадения уже есть |
| `(a -> b)[*].style.stroke: red` | применяется ко **всем** совпадающим соединениям (в скоупе ссылки), **включая объявленные после ссылки** — отложенное применение (проверено CLI: `a -> b` + `[*]` + `a -> b` → красные оба); совпадений нет вовсе → тихий no-op |
| `(c -> d).label: x` (не объявлено) | **создаёт соединение** `c -> d` с меткой `x` (неявные ноды `c`, `d`) |
| `(c -> d)[0].label: x` (не объявлено) | ошибка `indexed edge does not exist` |
| `(a -> b)[0].foo: x` (поле не reserved) | ошибка `edge map keys must be reserved keywords` |
| `(a -> b)[0]: value` (без `.field`) | шорткат метки = `.label: value` (SVG идентичен) |
| `(a -> b): value` / `(a -> b)[*]: value` | без индекса — создаёт новое соединение с меткой; `[*]` — метку всем совпадениям |
| `(a -> b)[0]` (голая, без присваивания) | no-op **без ошибки**, только если индекс в диапазоне; вне диапазона — ошибка `indexed edge does not exist` (проверено CLI) |
| `(a -> b)[ 0 ]`, `[00]`, `[ * ]` | валидны (пробелы и ведущие нули допускаются) |
| `(a -> b)[-1]`, `[x]` | ошибка `unexpected character in edge index` |
| `(a <-> b)[0]` | работает (форма стрелки входит в ключ) |
| `(a -> b)[0]` не видит `a <- b` | верно: ключ включает форму стрелки |
| `(a -* b)` / `(a *- b)` | `-*` — NoArrow (тот же ключ, что `--`); `*-` — ошибка `map value without key`. Расхождение проекта: `-*`/`*-` нормализуются в `->` (самосогласованно — и в объявлениях, и в ссылках) |
| повторные ссылки на одно ребро | складываются: `(a->b)[0].label` + `(a->b)[0].width` обе применяются |

### 2.2 Цепочки

| Запись | Поведение d2 (проверено) |
|---|---|
| `a -> b -> c` | объявляет две связи `a→b`, `b→c`, каждая с индексом 0 |
| `a -> b -> c: label` | метка применяется к **каждой** связи цепочки (2 метки в SVG) |
| `(a -> b -> c)[0].style.stroke: red` | компилируется: индекс применяется к каждой связи группы |
| `(a -> b -> c)[1]` | ошибка для **обеих** связей (обе должны иметь индекс 1) |
| `a -> b -> a -> b` + `(a -> b)[1].label` | метка на 3-м ребре (2-м `a->b`); индексы считаются по ключам пар в порядке объявления |
| `(a -> b)[0]` после переноса строки + `.label` | ошибка `invalid text beginning unquoted key` — продолжение ссылки **только на той же строке** |
| `(a -> b -> c): label` / `(a -> b -> c)[*].field: v` | по каждой паре: без индекса — создать ребро пары; `[*]` — всем совпадениям пары (отложенно) |

### 2.3 Скоупы (относительное разрешение)

| Запись | Поведение d2 |
|---|---|
| `a: { x -> y }` + внутри `(x -> y)[0].label: hi` | работает: путь разрешается **относительно текущего скоупа** (`a.x -> a.y`) |
| внутри `a: { … }` + `(a.x -> a.y)[0]` | ошибка `indexed edge does not exist` (путь снова трактуется относительно скоупа → `a.a.x`) |
| `a: { x -> y }` + на верхнем уровне `(a.x -> a.y)[0].label: hi` | работает (ссылка с полным путём видит вложенное соединение) |

### 2.4 Точечные пути в attr-телах

| Запись | Поведение d2 |
|---|---|
| `a -> b: { style.stroke: red }` | валидно, `d2 fmt` сохраняет `{style.stroke: red}` |
| `a -> b: { source-arrowhead.shape: triangle }` | валидно (структурный ключ) |
| `a -> b: { target-arrowhead.style.fill: red }` | валидно |
| `a: { style.stroke: red }` | валидно |
| `a -> b: { stroke: red }` / `a: { stroke: red }` | ошибка `stroke must be style.stroke` |
| `a -> b: { label.foo: bar }` | ошибка `unexpected field foo` |
| `a -> b: { foo.bar: x }` | ошибка `edge map keys must be reserved keywords` |

Точечные пути допустимы только у структурных ключей: для ребра — `style`, `source-arrowhead`, `target-arrowhead`; для ноды — `style`.

## 3. Зафиксированные решения

1. **Свёртка при парсинге (fold-on-parse).** Ссылка резолвится в целевое ребро (цели) и применяется как inline-атрибут: `.label` → поле `label` (+ `labelBlock`/`valueArray` как в `parseAttrBody`), прочие пути → `rawAttrs` **с полным путём** (`style.stroke: red`). Три типа целей по форме ссылки (паритет §2.1): индекс `[N]` → уже объявленное N-е ребро; **без индекса → новое ребро** (как объявление `a -> b: {…}`, добавляется в `order`); `[*]` → все совпадающие рёбра (в т.ч. объявленные позже — отложенное применение). Модель не меняется, новых типов стейтментов нет.
2. **Разрешение по тройке `(source, target, dir)`.** Обе конечные точки ссылки резолвятся через `resolvePath` относительно текущего скоупа → плоский id (паритет §2.3). `dir` — форма стрелки в ссылке. **Однопроходность (ссылка видит только объявленные раньше) верна только для индекса `[N]`**; без индекса — создание нового ребра; `[*]` — отложенное применение ко всем совпадениям (в т.ч. объявленным позже).
3. **Индекс:** явный `[N]` → N-е (0-базовое) совпадение; нет совпадения → **ошибка парсера** (паритет «indexed edge does not exist») — **независимо от присваивания**: голая ссылка с вне-диапазона `[N]` тоже ошибка (проверено CLI 2026-08-10: `(a -> b)[5]` → «indexed edge does not exist»; `(a -> b)[0]` → успех). Голая ссылка с **в-диапазона** `[N]` → тихий no-op. Без индекса → **создание нового соединения** (никогда no-op). `[*]` → все совпадения (отложенно); совпадений нет вовсе → **тихий no-op** (паритет §2.1).
4. **Цепочки в ссылках `(a -> b -> c)[N]` — паритет d2:** цикл по парам, индекс N применяется к каждой паре независимо; ошибка любой пары → ошибка парсера. Формы стрелок в цепочке независимы (`(a -> b <- c)` матчит `a→b` по `->` и `b→c` по `<-`).
5. **`(a)` — одиночный ключ без стрелки:** чистая ошибка парсера («ожидается соединение в ссылке '(...)'»), т.к. поведение d2 нестабильно (голая `(a)`/`(a)[0]` компилируются в пустой no-op — 0 нод/рёбер; `(a).label: x` — ошибка «map value without key»). Сознательное расхождение с d2 (строгое, в пользу ошибки).
6. **`null`:** обычная строка `"null"` (удаление через null не делаем).
7. **Комментарии при свёртке:** строки над ссылкой → `comments[]` целевого ребра; инлайн-комментарий ссылки → `trailingComment` ребра (если свободен), иначе `comments[]`; мульти-таргет (`[*]`) → к каждому целевому ребру.
8. **Продолжение ссылки — только на той же строке** (паритет §2.2). «Голая» ссылка (после `)`/`[N]` нет `.`/`:` на той же строке): **без индекса — создаёт соединение** (как `(a -> b)`); **с индексом — no-op только при в-диапазона `[N]`, ошибка при вне-диапазона** (паритет §2.1/§3.3, проверено CLI).
9. **Сериализация:** ссылки не сохраняются в исходной форме; на выходе канонический inline **без двоеточия** `a -> b {style.stroke: red}` (см. §8; `d2 fmt` даёт форму с двоеточием `a -> b: { style.stroke: red }` — обе валидны, SVG байт-в-байт одинаков). Содержимое сохраняется, форма — сознательно.
10. **Точечные пути (§2.4):** ребро — полный путь вербатим при первом сегменте ∈ {`style`, `source-arrowhead`, `target-arrowhead`}, одиночный RESERVED-ключ — как сейчас, иначе ошибка парсера; нода — полный путь при первом сегменте = `style`, первый сегмент ∈ RESERVED (≠ `style`) — ошибка, ∉ RESERVED — вложенные контейнеры (уже корректно).
11. **Цепочки в объявлениях:** `a -> b -> c: label|{…}` применяется ко **всем** связям цепочки (паритет §2.2; меняет существующий round-trip).
12. **`(a -> b)[0]: value` без `.field` — шорткат метки** (проверено CLI 2026-08-10): `d2` трактует это как `.label: value` (SVG идентичен `label`), не ошибка. `(a -> b): value` — создаёт новое соединение с меткой; `(a -> b)[*]: value` — метку всем совпадениям.

## 4. Токенизатор (`js/d2-parse.js`, `tokenize`)

Текущее состояние: `(`/`)` не токенизируются (попадают в unquoted-слова); `[`/`]` уже punct-токены; `*` в ключевой позиции → ошибка «globs (*) не поддерживаются» (строка 371). Изменения:

1. Добавить флаг **«начало стейтмента»**: `true` изначально и после токенов `nl`/`;`/`{`/`}`; сбрасывается после любого другого токена.
2. При `ch === "("`, `!inValue` и «начале стейтмента» → эмитить `punct "("` (lparen) и войти в режим **`refMode = true`**.
3. В `refMode`: `)` становится терминатором слова (чтобы `b)` → ident `b` + `punct ")"` rparen); после rparen — `refMode = false`.
4. В `refMode`: при `ch === "["` сканировать до `]` одним токеном **`refIndex`** (value = сырой контент: `"1"`, `"*"`, `"0"`); после — `refMode = false`. Внутри этого скана `*`/цифры не уходят в общий word-run и **не** триггерят glob-ошибку. Валидация в парсере: пробелы и ведущие нули допустимы (`[ 0 ]`, `[00]`, `[ * ]`); `[-1]`/`[x]` → ошибка «неожиданный символ в индексе соединения».
5. В остальных позициях `(`/`)` остаются литералами в словах (паритет: `x: (a)` — литерал, `a (b)` — ключ `a (b)`).

Ожидаемые токены для `(a -> b)[0].style.stroke: red`:
`lparen, ident(a), arrow(->), ident(b), rparen, refIndex(0), punct(.), ident(style), punct(.), ident(stroke), punct(:), ident/str(red)`.

## 5. Парсер (`parseStatement` → `parseRef`)

1. В `parseStatement` (строка 887): первым делом проверять `punct "("` → `parseRef()`.
2. `parseRef`:
   - lparen; затем цикл: `parsePath()` (путь конечной точки), `isArrow()` (форма стрелки) → сохранить, `parsePath()` (следующая точка), пока не rparen. Собрать пары `{srcPath, dir, tgtPath}` (цепочка). Пути с `*` в начале → ошибка «globs (*) не поддерживаются» (существующая). Одиночный путь без стрелки → ошибка «ожидается соединение в ссылке '(...)'».
   - опционально `refIndex` (значение: цифры или `*`; нормализация `00`→0, пробелы допускаются; `-`/буквы → ошибка «неожиданный символ в индексе соединения»).
   - далее: если на **той же строке** идёт `punct "."` → `parsePath()` даёт `.field[.sub…]`, затем `:`, затем `parseValue()` (та же обработка label/block/array/trailingComment, что в `parseAttrBody`);
   - если `:` без `.field` — **шорткат метки** (§3.12): значение идёт в `label`/`labelBlock`/`valueArray` как `fieldSegs = ['label']`;
   - иначе («голая» ссылка): **без индекса — создать соединение** (§3.8); **с индексом — no-op**.
3. **Резолв пары** (общий хелпер `resolveEdgeRef(srcPath, dir, tgtPath, index)`):
   - `resolvePath(srcPath)` / `resolvePath(tgtPath)` → плоские id (как в `createEdge`);
    - `index` = число → N-е совпадение в `graph.edges` в порядке создания по `(source, target, dir === '->' ? undefined : dir)` — поле `dir` хранится только при `!== '->'`; нет → **ошибка** «индекс соединения (…)[N] вне диапазона» с подсказкой (число найденных записей / «объявите соединение до строки ссылки»; line/col ссылки) **при присваивании и у голой ссылки с вне-диапазона индексом**; голая ссылка с в-диапазона индексом → no-op;
   - `index` не задан → **создать новое ребро** тем же путём, что `createEdge` (неявные ноды, дописывание в конец `order`), цель — оно;
   - `index` = `*` → все совпадения (мульти-таргет) в текущем `graph.edges`; совпадений нет → записать в **отложенные glob-ссылки** (`pendingGlobs`: плоские id пары + fieldSegs + значение + комментарии); в конце парсинга применить каждую отложенную ссылку ко всем совпадениям по сохранённым плоским id (скоуп учтён при резолве); совпадений всё ещё нет → тихий no-op.
4. **Фолдинг** (общий хелпер `foldRefAttrs(edge, fieldSegs, value, inlineComment)`, вызывается для каждой цели — для `[*]` для каждого совпавшего ребра):
   - `fieldSegs = ['label']` → `label`/`labelBlock`/`valueArray` (поведение `parseAttrBody`);
   - иначе — по правилу §3.10: первый сегмент ∈ {`style`,`source-arrowhead`,`target-arrowhead`} → `rawAttrs` с полным путём `style.stroke: red`; одиночный сегмент ∈ RESERVED → `rawAttrs`; иначе → ошибка «ключ недопустим для соединения» (паритет «edge map keys must be reserved keywords»).
5. **Комментарии** — по §3.7: `pending` (строки над ссылкой) → `consumePending` на первое целевое ребро (для без-индекса — на созданное); инлайн `# …` → `trailingComment` (если свободен) иначе `comments[]`; для мульти-таргета — каждому.
6. Вложенность скоупов: `parseRef` вызывается и из `parseStatement` внутри `parseBlock`, поэтому `resolvePath` уже работает относительно `curScope()` (паритет §2.3) без доп. изменений.

## 6. Фикс точечных путей (корневая причина бага)

Текущий код:
- `parseEdgeAttrBlock` (строка 746): `parseAttrBody(ed, p[p.length - 1].value)` — **только последний сегмент** пути → `style.stroke: red` становится `rawAttrs: ["stroke: red"]` → на выходе `a -> b {stroke: red}` (невалидный D2).
- `parseNodeOrAttr` (строка 832): многосегментный путь не проходит проверку `single && RESERVED[key]` (строка 839) и уходит в `declareNode(pathTokens)` → `style.stroke` превращается во вложенные контейнеры `style { stroke { label: red } }` (валидно, но другой смысл).

Изменения:
- `parseEdgeAttrBlock`: вместо последнего сегмента передавать в обработчик весь путь + признак; обработчик применяет правило §3.10.
- `parseNodeOrAttr`: если `pathTokens.length > 1` и первый сегмент ∈ RESERVED:
  - первый сегмент === `style` → `rawAttrs` с полным путём (значение — через существующий `parseValue`, block/array — как в `parseAttrBody`);
  - иначе → ошибка парсера «поле <сегмент> не может иметь под-поля» (паритет «unexpected field»);
  - если первый сегмент ∉ RESERVED → текущее поведение (вложенные контейнеры, корректно) без изменений.
- Правило применяется и к свёртке ссылок (общий хелпер из §5.4).

## 7. Цепочки — паритет d2

1. **Объявления** (`js/d2-parse.js:805-827`): `: value` и `: { … }` после цепочки сейчас применяются к `edges[edges.length - 1]` — переделать на **все** рёбра цепочки. Блок `{…}` парсится один раз в буфер (label/rawAttrs/trailingComment), затем копируется в каждое ребро. Комментарии внутри блока — только последнему ребру цепочки (документированное упрощение: текущая модель выносит их выше ребра в `comments[]`, дублировать на каждую связь не нужно).
2. **Ссылки на цепочки** `(a -> b -> c)[N]` / `(a -> b -> c)` / `(a -> b -> c)[*]`: цикл по парам из §5.2/§5.3 — каждая пара резолвится независимо со своим `dir`: `[N]` — N-е совпадение пары (ошибка любой пары → ошибка парсера), без индекса — создать ребро пары, `[*]` — все совпадения пары (отложенно).
3. Следствие: round-trip документов вида `a -> b -> c: label` меняется (метка теперь на всех связях) — зафиксировать тестами паритета.

## 8. Сериализация (`js/d2-serialize.js`)

- Правок в `emitEdge` не требуется: после фикса §6 rawAttrs уже содержат полный путь, и вывод даёт `a -> b {style.stroke: red}` (канонический inline; форма «один простой атрибут → одна строка» уже есть).
- **Решение пользователя (2026-08-10): форма вывода — свёртка (Вариант A).** Ссылки эфемерны, вывод всегда стандартный inline (форма без двоеточия, §3.9). Сохранять ссылки в модели/выводе (Вариант B) отклонено: ссылки стали бы стейтментами в `order`, merge-идентичность по `(src,dst,стрелка,индекс,поле)` хрупкая (индекс чувствителен к порядку), их нужно исключать из рендера/выбора. Возможный «сжатый» режим для мульти-таргета — отдельный будущий кандидат.
- **Форма блока — без двоеточия** (`a -> b {label: 1}`, как сейчас в `emitEdge`). Решение пользователя: без двоеточия короче и легче читается. Обе формы валидны и дают **байт-в-байт одинаковый SVG** (проверено CLI); `d2 fmt` при желании добавит двоеточие, но это не требуется. Микроправку сериализатора НЕ делаем.
- **Эталонные пары «исходник → вывод»** (сверено с `emitEdge`, формат при реализации):

| Исходник | Вывод |
|---|---|
| `a -> b` + `(a -> b)[0].label: Отправка` | `a -> b {label: Отправка}` |
| `a -> b` + `(a -> b)[0].style.stroke: red` | `a -> b {style.stroke: red}` |
| два атрибута через две ссылки | `a -> b {` / `  style.stroke: red` / `  style.fill: yellow` / `}` |
| `a -> b` + `(a -> b).label: X` | `a -> b` + `a -> b {label: X}` (без-индекс ссылка создаёт второе параллельное ребро — паритет d2) |
| `(a -> b -> c)[0].style.stroke: red` | `a -> b {style.stroke: red}` + `b -> c {style.stroke: red}` |

- Проверить инвариант: `stripMarkers(serializeAnnotated(g)) === serializeClean(g)` остаётся верным.
- refText-механизм (сохранение однострочной/многострочной формы блока) на ссылки не распространяется: после свёртки ссылки в тексте нет, форма блока ребра — дефолтная/из refText самого ребра.

## 9. Ошибки (русские, с line:col)

| Ситуация | Сообщение |

| индекс вне диапазона / соединение не объявлено с индексом | «индекс соединения (src -> dst)[N] вне диапазона: выше по тексту нет записей 'src -> dst' — объявите соединение до строки ссылки» (0 записей) / «… вне диапазона: выше по тексту найдено M (нумерация с 0: [0] — первая, последняя — [M-1])» (индекс ≥ M) |

## 10. Визуальный редактор (ответ на вопрос «правильно ли отобразится»)

- **Структура, позиции, связи — да, без изменений и без регрессий для индексных и `[*]`-ссылок.** Свёртка пишет в существующую модель (`label`/`rawAttrs` существующих рёбер), новых типов в `order` нет; merge сохраняет позиции (`hasPos`/маркеры не трогаются); `order` не перестраивается. **Исключение — ссылки без индекса: они создают новое параллельное ребро** (как объявление), на схеме появляется дополнительная связь — это паритет d2 (§2.1), рендер нового ребра штатный.
- **Метка через ссылку** `(a -> b)[0].label: hi` — рендерится как обычная метка ребра (`edge.label`).
- **`style.*` / `width` / `tooltip` / `icon` (rawAttrs) — НЕ применяются к отрисовке.** Ребро/блок остаются в дефолтной теме. Это **существующее** ограничение («style не визуализируется», статус ⚠️ в `d2-visualization-coverage.md:116,264`), не регрессия от нововведений: rawAttrs копируются в модель (index.html:326/334) и хранятся lossless для round-trip. Диаграмма не «ломается», просто не раскрашивается. Применение `style.fill/stroke` — отдельный кандидат (`d2-visualization-coverage.md:268`).
- **Цепочка с меткой** `a -> b -> c: label` — видимое изменение: метка появится на обеих связях (сейчас только на последней). Рендерится корректно.
