**Найденные при реализации расхождения плана с реальностью (уже исправлены в коде):**

1. **Сигнатура `createHistory`** — модуль принимает **число** (`createHistory(limit)`), а не объект `{limit}` как в плане-черновике. Вызов в UI — `D2HIST.createHistory(undoLimitPref())`. Объектная форма тихо падает на дефолт 100 (проверено тестом).
2. **Нормализация `currentGraph()`** (§3.2 «обе стороны через одну нормализацию») оказалась **неполной** — это давало ложные записи в историю:
   - узлы, созданные визуально (`addBlock`), не имеют ключа `implicit`, а парсерные — имеют `implicit: false` (парсер ставит ключ явно);
   - у визуально созданного ребра с пустой подписью — `label: ""`, у парсерного — `label: null`.
   Эмпирически: whitespace-правка создавала патч с нетронутым блоком. Исправлено добавлением в `currentGraph()`: `implicit: !!n.implicit` (узлы) и `label: e.label || null` (рёбра). Сам `diffStates` на сырых значениях `""`/`null` различает их — нормализация обязательна на уровне `currentGraph()`.
3. **`applyStatePatch` не пересобирал рёбра при патче только с `order`** (правка текста, переставившая строки рёбер): массив `edges` оставался в пост-порядке, порядок отрисовки расходился с восстановленным `order`. Исправлено: пересборка по `state.order` выполняется при `patch.edges || patch.order`.

## 1. Текущее состояние (реализовано)

**Модуль `js/d2-history.js`** — создан (223 строки, ES5 UMD, без DOM, как остальные `js/*`). Самодостаточен, в UI не подключён, тестами не покрыт. Не закоммичен (untracked, вместе с `docs/plans/undo-redo-and-browser-files.md`).

Экспорт (CommonJS `module.exports` + `global.d2history`):

```
createHistory(limit)          → { limit, stack: [], redo: [] }
pushState(hist, patch)        // push; при превышении limit — shift старых; очистка redo
undo(hist) → patch | null     // stack → redo
redo(hist) → patch | null     // redo → stack
canUndo(hist) / canRedo(hist) // boolean
clearHistory(hist)
diffStates(prevState, nextState) → patch | null
applyStatePatch(state, patch, dir)  // dir: "before" | "after"; мутирует state
```

Внимание: **фактические имена полей истории — `stack` и `redo`** (в родительском плане эскизно названы `undoStack`/`redoStack`). В коде и тестах — `h.stack`, `h.redo`.

**Патч** (`diffStates`):

```js
{
  nodes: { "<id>": { before: <node|null>, after: <node|null> } },
  edges: { "<id>": { before: <edge|null>, after: <edge|null> } },
  order: { before: [...], after: [...] } | null,
  viewport: { before: {...}, after: {...} } | null,
  showComments: { before: bool, after: bool } | null
}
```

- `before: null` — элемент добавлен действием; `after: null` — удалён.
- `nodes`/`edges` — только реально изменившиеся по id.
- Сравнение значений — **каноническое**: рекурсивная сортировка ключей объектов перед `JSON.stringify` (порядок ключей нод из `addBlock` и из парсера после merge различается; наивный `stringify` считал бы одинаковое «изменённым»).
- **`idCounter` исключён из сравнения** и в патч не попадает (после текстового merge пересчитывается детерминированно, не отражает намерений).
- `applyStatePatch` мутирует state на месте: `state.nodes` — **Map** (id → узел), `state.edges` — массив. Рёбра пересобираются в порядке `state.order` (вставка на стабильную позицию по id, не `push`) — сохраняется порядок отрисовки. Значения клонируются при материализации — последующие мутации живой ноды не портят `before`/`after` (повторные undo/redo корректны).

Проверено вручную (`node -e`): diff → apply "after" (redo) → apply "before" (undo) round-trip корректен для добавления ноды + изменения order.

## 5. Ловушки и инварианты

- Фактические имена полей истории — `stack`/`redo` (не `undoStack`/`redoStack`).
- `diffStates` не учитывает `idCounter` — не ждать его в патче.
- Обе стороны diff — через одну нормализацию `currentGraph()`; иначе ложные изменения на каждой ноде. **Нормализация обязана включать `implicit` (узлы) и `label: e.label || null` (рёбра)** — визуальные и парсерные представления различаются (§0.2).
- `applyStatePatch` клонирует значения и пересобирает рёбра по `state.order` — не заменять на наивный `push`. Пересборка выполняется при `patch.edges || patch.order` (§0.3).
- Сигнатура `createHistory(limit)` — **число**, не объект (§0.1).
- Хоткеи — только вне `INPUT`/`TEXTAREA`, иначе ломается нативный undo текста.
- `applyPatchToLive` сбрасывает `textTimer` (несостоявшееся слияние текста отбрасывается — осознанная семантика явной команды).
- Память: в стеке только патчи (O(изменённых)); полные снапшоты — транзиентно при фиксации действия.
- Toggle «Скрыть/Показать позиции» пишет в историю (меняет `showComments`) — это осознанное поведение, см. §3.2.
