# Разработка D2 visual editor

## 1. Окружение

- **Node.js ≥ 20** (разработка велась на v20.19.4). Тесты — встроенный `node:test`.
- **Браузер** — только для E2E (`puppeteer-core`, без встроенного Chrome; нужен системный Chrome/Chromium).
- **`d2` CLI** — опционально: тесты паритета компилируют оба представления в SVG и **сами пропускаются**, если `d2` нет в `PATH` (`exec("d2", ["--version"])` бросает → `t.skip`).
- **Интернет** — приложение открывается как `file://` и грузит `@xyflow/system` с CDN (`unpkg`). Без сборки и без бинарных зависимостей.

## 2. Запуск

```bash
# приложение (без сборки)
xdg-open index.html
# или любой статический сервер:
python3 -m http.server 8080   # затем http://localhost:8080

# тесты
npm test                      # 136 юнит-тестов (node:test)
npm run test:ui               # 15 E2E-сценариев (puppeteer-core)
CHROME=/path/to/chrome npm run test:ui   # переопределить Chrome
```

## 3. Структура и стиль кода

### `js/*.js` — ES5 UMD-модули (без DOM)

```js
(function (global) {
  "use strict";
  function foo() { /* var, не const/arrow */ }
  var api = { foo: foo };
  if (typeof module !== "undefined" && module.exports) module.exports = api;
  global.d2mod = api;   // имя глобала = имя модуля
})(typeof globalThis !== "undefined" ? globalThis : this);
```

- `var`, функции, `single quotes`, 2 пробела, точки с запятой. **Без DOM** — только чистые функции над v2-графом.
- Не добавляйте комментарии в код, если пользователь не просил (существующие поясняющие — не удалять).
- Новые функции не пишут в глобальное состояние модуля, если это не документировано.

### `index.html` — современный JS (инлайн)

- `const`/`let`, стрелки, шаблонные строки, 2 пробела, `single quotes`.
- Живые структуры: `nodes` — `Map`, `edges` — массив, `order` — массив id. UI — тонкая обвязка над модулями.
- Строки интерфейса/статусы — **на русском**.

### Экспорт API модулей (глобалы в UI)

| Модуль | Глобал |
|---|---|
| `d2-serialize.js` | `window.d2mod` → `D2S` |
| `d2-parse.js` | `window.d2parse` → `D2P` |
| `d2-merge.js` | `window.d2merge` → `D2M` |
| `d2-layout.js` | `window.d2layout` → `D2L` |
| `d2-sort.js` | `window.d2sort` → `D2SORT` |

Порядок подключения в `index.html`: serialize → parse → merge → layout → sort (зависимостей между ними нет, но так удобнее читать). Новый модуль добавляется и в `<script>`, и в этот список.

## 4. Тестирование

### Юнит-тесты (`test/<module>.test.mjs`)

```js
import { createRequire } from "node:module";
import { test } from "node:test";
import assert from "node:assert/strict";
const require = createRequire(import.meta.url);
const { parseD2 } = require("../js/d2-parse.js");
```

- Тесты `.mjs`, модули `.js` грузятся как CommonJS через `createRequire`. **`"type": "module"` в package.json не добавлять** — сломает этот механизм.
- Хелперы построения графа (`node()`, `edge()`, `graphOf()`) дублируются в тест-файлах — по сложившейся практике каждый тест-файл самодостаточен.
- Специфика `node:test`: `t.skip()` для опциональных (CLI), `{ timeout }` для E2E, вывод `node --test test/`.

### E2E (`test/ui-smoke.test.mjs`)

- `puppeteer-core` + системный Chrome (`CHROME` env или `/usr/bin/google-chrome-stable`).
- Страница открывается как `file://`; localStorage очищается через `evaluateOnNewDocument`.
- Нативных `prompt()`/`confirm()` в приложении нет — всё редактирование через собственный модальный диалог (`#modal-overlay`, `openEditDialog`): ждём `#modal-overlay` `visible`, заполняем `#modal-input` через `$eval`, закрываем кликом `#modal-ok` (или Enter).
- Тест ждёт debounce (3 c) после `input`-события: проверяются статусы «Синхронизировано», «Новых блоков: N (авто-позиция)», «Ошибка D2: строка N — …».
- Обязательно проверяйте отсутствие ошибок страницы (`page.on("pageerror")`).
- Split-button «Копировать» + шеврон (`#btnCopyMenu`, меню `#copy-menu` с пунктами `data-act`: `paste`/`replace`/`import`/`export`). Импорт идёт через скрытый `#import-file` (`page.waitForFileChooser()`), экспорт — через нативный диалог `window.showSaveFilePicker()` (с fallback на `Blob` + `a[download]`). Экспорт D2 всегда дописывает расширение `.d2` (если юзер ввёл имя без него — файл переименовывается через `handle.move`), а имя файла запоминается в `localStorage["d2editor:ui:v1"]` (поле `exportName`) и предлагается при следующих экспортах. Форматные пункты `export-drawio`/`export-mermaid`/`import-mermaid` — пока стабы («… — в разработке»), реализуются по очереди; `export-svg` уже реализован (следующий пункт).
- **Экспорт в SVG** (`export-svg`, `buildSVG`): самодостаточный векторный документ без `foreignObject` — рёбра как `<path>` + `<marker>`, блоки как `<rect>` (`rx=8`, у контейнеров `stroke-dasharray`), все стили инлайн-атрибутами, шрифты только из системного стека, белый фон, `viewBox` по bounding-box всех элементов + отступ 40px. Текст с переносом: `wrapLabel` меряет ширину через canvas `measureText` и рендерит строки как отдельные `<text>`; baseline считается из `actualBoundingBoxAscent/Descent` (без `dominant-baseline` ради совместимости); подпись ребра — два слоя `<text>` (белая обводка + тёмная заливка) вместо `paint-order`. **Порядок слоёв** (важно, покрыто тестом): фон контейнеров → фоны блоков → рёбра+подписи рёбер → подписи блоков, чтобы стрелки внутри групп не перекрывались полупрозрачной заливкой; подписи без `label` у ребра не выводятся (`label != null`, а не truthy-проверка — `String(null)` даёт `"null"`).
- **Headless-ограничения**: `navigator.clipboard.writeText` в headless на `file://` отклоняется (`NotAllowedError`) — для чтения буфера в тестах стаб `navigator.clipboard.readText`; нативный диалог сохранения не автоматизируется — `showSaveFilePicker` стабится фейковым handle (перехватывает `write`), fallback-путь проверяется стабом `URL.createObjectURL`/`HTMLAnchorElement.prototype.click`.

### Что покрыто (136 тестов)

- `parse`: квотинг, пробелы в ключах, вложенность, пути, рёбра/цепочки/списки, `#` и `//` комментарии, `@d2pos` + `trailingComment`, заголовочные/хвостовые комментарии, `rawAttrs`, `style`-блок, ошибки синтаксиса, пустой ввод.
- `serialize`: паритет clean/annotated, `stripMarkers`, `POS_RE` (якорь конца строки), целые координаты, порядок по `order` (hoisting родителя, дубликаты id, циклы parentId), d2 CLI-паритет.
- `merge`: 20 сценариев раздела «Поведение» плана + end-to-end стабильность.
- `layout`: центр вьюпорта, цепочки слева/справа, дети в контейнере, плотные кластеры без пересечений, `hasPos` не трогается.
- `sort`: цепочки, ромбы, циклы, self-loop, контейнеры (deferred-цели), cross-scope стрелки, вложенные контейнеры, детерминизм, идемпотентность, иммутабельность входа.
- `ui-smoke` (15 E2E): загрузка/seed, toggle clean↔annotated, переименование с сохранением позиции, авто-позиция новой ноды, ошибка D2 не ломает граф, сортировка, миграция v1→v2, двойной клик по блоку/стрелке, модалка и её перетаскивание, меню «Копировать/Заменить/Импорт/Экспорт» (включая стабы), принудительный `.d2` и запоминание имени файла, SVG-экспорт (самодостаточный документ, порядок слоёв, отсутствие `null`-подписей), перекрытие панели кнопок.

## 5. Ловушки и известные ограничения

- **`hasPos`** — если нода не помечена, `placeNewNode` может сдвинуть её; позиция «коммитится» только установкой `hasPos:true`.
- **Не переписывайте textarea во время ввода** — ломается каретка. Только: структурные изменения после debounce, «чистая» перегенерация `queueGen`, явные команды (toggle/sort).
- **Маркер-подделка**: пользовательский комментарий, заканчивающийся на `# @d2pos x,y`, трактуется как позиционный (зарезервированный формат). Документированный редкий конфликт.
- **Пробелы в ключах**: `a b c` — одна нода. Не «чинить» токенизатор без сверки с CLI `d2`.
- **`//` в середине ключа** — часть ключа (`Client // note`), комментарий только на границе токена.
- **Не поддерживается**: классы/`@`-директивы, импорты, переменные/функции/массивы, `style` как грамматика, `near`, HTML-метки. Встречается → `rawAttrs` или ошибка со строкой, но не молчаливый сброс.
- **localStorage**: ключ `d2editor:v1`, payload `v:1`. Не переименовывать ключ без миграции. UI-предпочтения — отдельный ключ `d2editor:ui:v1` (`{codeWidth, exportName}`).
- **`d2` CLI-тесты пропускаются** без бинаря в `PATH` — не считайте это падением.
- **E2E в headless**: вместо нативных `prompt()`/`alert()` приложение использует собственный модальный диалог `#modal-overlay` — тест заполняет `#modal-input` и жмёт `#modal-ok`.

## 6. Порядок работы

1. Прочитать `docs/architecture.md` и `docs/plans/d2-editor-sync.md`.
2. Менять логику в `js/*.js` (чистые функции) + тесты рядом; UI — только обвязка в `index.html`.
3. После изменений: `npm test`; если трогали UI-поток — `npm run test:ui`.
4. Ветки: работа на `feature/*`, интеграция — в `main`. Коммиты/слияния — только по явной просьбе пользователя.
