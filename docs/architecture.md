# Архитектура D2 visual editor

## 1. Общая модель

**Граф — источник истины** для хранения и структуры схемы. **D2-текст — проекция графа**, получаемая сериализаторами. Это позволяет «не терять позиции»: они живут в графе и заново сериализуются для каждого элемента.

```
            parseD2 (текст → граф)
D2-текст  ─────────────────────────►  граф v2
   ▲                                   │
   │  serializeClean /               mergeGraph
   │  serializeAnnotated               │ (перенос позиций из текущего
   └───────────────────────────────────▼  графа в распарсенный)
```

Правило приоритета позиций при правке текста:

1. **Маркер `# --- @d2pos x,y` в тексте авторитетен** (пользователь правит числа в аннотированном виде).
2. Нет маркера (чистый вид) → позиция переносится из текущего графа через **merge-эвристики**.
3. Совсем новый элемент без маркера → **авто-расстановка** (`placeNewNode`).

## 2. Модель графа (v2)

```js
{
  v: 2,
  nodes: [{
    id: "db",                 // локальный ключ сегмента; полный путь — цепочкой parentId
    label: "Database",
    x: 40, y: 60, w: 150, h: 70,
    parentId: "API Server",   // null для корней
    children: [],             // id прямых детей (порядок = порядок внутри {})
    comments: [],             // комментарии над элементом: строка для `#`, `{text, block:true}` для `"""…"""`
    trailingComment: null,    // инлайн-комментарий в конце строки элемента
    rawAttrs: [],             // сырые атрибуты, не вошедшие в модель
    valueArray: undefined,    // атрибут-массив `x: [a, b]` (нода/ребро; метка пустая, паритет с d2)
    labelBlock: undefined,    // блочная строка-метка `{tag, quote, value}`
    hasPos: true,             // «позиция зафиксирована» (см. раздел 4)
    implicit: false           // неявная нода из `a -> b`
  }],
  edges: [{ id: "e1", source: "Client", target: "API Server", label: "HTTPS",
            comments: [], trailingComment: null, rawAttrs: [], dir: "<->" }],
```

Поле ребра `dir` (`'->' | '<-' | '<->' | '--'`) хранится **только при `!== '->'`** (дефолт, обратная совместимость с legacy-графами). `source`/`target` — всегда текстовый порядок (`a <- b` не разворачивается). Для layout/sort направление трактуется по «семантическим концам»: при `dir === '<-'` семантический источник = `target`, цель = `source` (локальный хелпер `edgeEndpoints` в `d2-layout.js` и `d2-sort.js`).
  order: [id, id, ...],       // ЕДИНСТВЕННЫЙ порядок эмиссии: ноды и рёбра вперемешку, как в тексте
  headerComments: [],         // комментарии до первого элемента
  trailingComments: [],       // комментарии в конце файла
  idCounter: N,
  viewport: { x, y, zoom }
}
```

Хранилище: `localStorage["d2editor:v1"]`, payload с полем `v: 1` (legacy-совместимость; имя ключа не менялось со старой версии приложения). Поля `order` и `showComments` появились позже — при их отсутствии `order` строится как `defaultOrder` = `treeOrder()` + рёбра в конце.

### Семантика id

- `id` — **локальный** ключ сегмента (`"db"`, `"API Server"`), полный путь `a.b.c` восстанавливается цепочкой `parentId`.
- Ключи с пробелами и спецсимволами при сериализации берутся в кавычки через `d2Key` (`"API Server"`); внутри графа id хранится без кавычек.
- `"b.c"` в тексте — литерал, а не путь: приоритет у самого длинного ключа.

## 3. Модули и их обязанности

| Модуль | Глобал (UI) | Отвечает за |
|---|---|---|
| `js/d2-serialize.js` | `D2S = window.d2mod` | Эмиссия текста по `order`: `serializeClean` (без маркеров), `serializeAnnotated` (с маркерами), `stripMarkers`, квотинг `d2Key`, `treeOrder` (только ноды, pre-order, защита от циклов), `defaultOrder` |
| `js/d2-parse.js` | `D2P = window.d2parse` | Токенизатор + `parseD2`: построение v2-графа с `order` по тексту, извлечение `@d2pos`, отделение `trailingComment`, комментарии, `rawAttrs`, ошибки с номером строки |
| `js/d2-merge.js` | `D2M = window.d2merge` | `mergeGraph(parsed, current, selection)`: матчинг по полному пути → эвристики → авто-позиция; перенос полей (`transferNodeFields`), `order` переводится на новые id; рёбра матчатся по записи (source,target,dir) на новых id |
| `js/d2-layout.js` | `D2L = window.d2layout` | `placeNewNode(graph, nodeId, opts)`: якорь (сосед по ребру → родитель-контейнер → центр вьюпорта) + спиральный поиск свободного места |
| `js/d2-sort.js` | `D2SORT = window.d2sort` | `sortByArrows(graph)`: DFS pre-order по скоупам, возвращает новый граф |
| `js/d2-shapes.js` | `D2SHP = window.d2shapes` | Реестр 18 форм (data-driven): `renderShape` → SVG-пути, `outlinePoints` → полигон контура, `outlineIntersect` → точка выхода луча, `normalizeRatio` → 1:1, `SHAPE_NAMES` |

## 4. Авто-расстановка (`d2-layout.js`)

`placeNewNode(graph, nodeId, { center })` — чистая функция, **не трогает ноды с `hasPos:true`**, присваивает позицию и ставит `hasPos:true`.

1. **Якорь**: если есть входящее/исходящее ребро — рядом с соседом (новая нода как `source` → слева от цели; как `target` → справа от источника; `GAP = 32`). Направление трактуется по семантическим концам (`edgeEndpoints`): для `<-` новая нода-семантический источник — слева от цели.
2. Иначе есть родитель-контейнер → внутри него с отступами `PAD/HEAD` (24/28), поиск только вправо/вниз от левого-верхнего угла.
3. Иначе — центр вьюпорта (`opts.center` из UI).
4. **Свободное место** — спираль вокруг якоря (шаг `STEP = 40`, запас `MARGIN = 8`, лимит 2000 кандидатов), кандидат проверяется на пересечение со всеми чужими abs-боксами. Сложность `O(N·tries)` на ноду.

Родительский бокс не считается препятствием для детей (дети по определению внутри); пары родитель-потомок исключаются и в тестах.

## 5. Merge-слой идентичности (`d2-merge.js`)

`mergeGraph(parsed, current, selection)` → `{ graph, added, removed, selectedId, selectedEdgeId }`.

- **Проход 1** — точный матч по полному пути (`a.b.c`).
- **Проход 2** — эвристики для несовпавших: `candidateScore` ≥ `MATCH_THRESHOLD` (3):
  - маркер на той же позиции +3;
  - label совпадает +2;
  - тот же родитель +1;
  - общие соседи по label +2 каждый (макс +4).
- Переименованный контейнер распространяет новое имя на потомков (`a.b → x.b`).
- Перенос полей: если у распарсенной ноды нет маркера, берутся `x/y` из текущей (позиция «выживает»); `w/h` переносятся всегда.
- Рёбра матчатся по записи `(source, target, dir)` на **новых** id — `a <- b` и `b -> a` разные ребра; приоритет совпадению label (смена подписи сохраняет id). Новые рёбра получают распарсенный id, если он свободен, иначе следующий `eN`.
- `order` переводится на новые id; несуществующие id отбрасываются, недостающие дописываются.
- Следствие (не баг): правка имени при том же маркере считается переименованием, а не добавлением.

## 6. Сериализация и паритет

- `serializeClean`/`serializeAnnotated` эмиттят по `order`: нода с детьми — блоком рекурсивно (дети уже выведенные внутри поддерева на верхнем уровне пропускаются); рёбра — отдельно с пустой строкой перед секцией.
- Аннотированный вид дописывает маркер в конец строки: `Client # note # --- @d2pos 60,300` (инлайн-комментарий пользователя остаётся на месте).
- **Форма блоков `{…}`**: скоуп с ровно одним простым атрибутом (метка-не-id, `shape`, один `rawAttr` без переводов строк) и без детей/`labelBlock` по умолчанию сериализуется в одну строку `id: {attr: v}`; все остальные случаи — многострочный блок. Опции `{refText}` / `{refIds}` (Map id→`inline` от `D2P.inlineIds`) сохраняют исходную форму блока: написанное в одну строку остаётся однострочным, в три строки — трёхстрочным. UI передаёт `refText` во всех перегенерациях textarea (по проверке «чистоты» `out.value === lastGraphText`).
- **Перенос строки в метке** (`\n`-эскейп в тексте → реальный `\n` в графе): кодовая форма — всегда `"…\n…"` с пробелами вокруг `\n` (`[ \t]*\x0A[ \t]*` → ` \n `); блок-строка для многострочных меток не синтезируется (только из пользовательского `labelBlock`). Визуально перенос рендерится переводом строки: интерактивные метки нод — `white-space: pre-line` (`.nlabel`), метки рёбер — `<tspan>` на разных базовых линиях (интерактив и SVG-экспорт через `tspanLines`); `wrapLabel` в экспорте уважает жёсткие `\n` как принудительные разрывы.
- **Паритет**: `stripMarkers(serializeAnnotated(g))` === `serializeClean(g)`. Проверяется юнит-тестами и через `d2` CLI (оба варианта компилируются в идентичную структуру).

## 7. Пайплайны данных в UI (`index.html`)

### Правка текста (левая панель)

`input` → debounce `TEXT_EDIT_MS` (3 c) → `onTextEdit`:

1. `parseD2(out.value)`; при ошибке — статус «Ошибка D2: строка N — …», граф и текст **не трогаются**.
2. `mergeGraph(parsed, currentGraph(), { selectedId, selectedEdgeId })`.
3. Для каждого `added` → `placeNewNode(merged.graph, id, { center: centerFlow() })`.
4. `applyGraph(merged.graph)` → обновить selection → `renderEdges() + renderNodes() + renderHint()` → `queueSave()`.
5. Если `added || removed` → `regenerateTextView()` + статус «Новых блоков: N (авто-позиция)»; иначе `lastGraphText = out.value` + «Синхронизировано».

### Мутации схемы (правая панель)

Drag, добавить блок, стрелка, группа, delete, rename → `render()` → `queueSave()` (400 мс) + `queueGen()` (1 c). `queueGen` переписывает textarea **только если** `out.value === lastGraphText` (текст «чист»), чтобы не ломать каретку.

**Выделение** (`selectedId`/`selectedEdgeId`, взаимоисключающие): клик по блоку/стрелке выбирает; **повторный клик по тому же элементу снимает выбор** (toggle — `selectedId === n.id ? null : n.id` и аналогично для ребра в обработчике `svgEl`); клик по **пустому месту** визуального поля (`clearSelection`, цель — сам `pane`/`viewport`) снимает выбор и блока, и стрелки.

### Toggle «Скрыть/Показать позиции»

Переписывает textarea только если тот «чист» (равен последней сериализации графа). Если в textarea неслитая правка или ошибка — лишь переключает флаг `showComments`; новое представление применится при следующем успешном merge.

### Хранение

`queueSave` → `saveState` пишет `{v:1, nodes, edges, idCounter, viewport, order, showComments}` в `localStorage["d2editor:v1"]`. Загрузка: `loadState` → при отсутствии `order` строится `defaultOrder` (миграция v1 → v2). Сборка мусора: `syncOrder()` убирает id удалённых нод/рёбер и дописывает недостающие.

**Персистентность графа в localStorage и его границы.** localStorage хранит текст как строку (не БД и не «файл»): нет списка, перезапись одним документом, риски переполнения ~5 МБ и очистки. Отсюда — файлы в браузере (см. ниже).

### Модальные диалоги

Единый каркас `showModal(opts)` → одна сессия `s` (повторный вызов закрывает предыдущую), один одиночный слой (`#modal-overlay`), DOM — `#modal-box` (ширина 500px, перетаскивается за `#modal-title`), `#modal-content`, `#modal-input`, кнопки `#modal-ok`/`#modal-cancel`. Сессия: `setTitle`, `setText` (основная строка в `#modal-content`), `setContent(el)` (подменяет контент), `setShowInput`, `setButtons`, `setBehavior`, `value`, `close`, `closed` (Promise).

Опции: `behavior: { allowOverlayClose, allowEscapeClose, onEnter, onEscape }`, `inputValue`, `valueType` (`"text"`/`"num"`), `ok` — обработчик подтверждения, `cancel`. Возврат `s` после `ok`/`cancel` — через `resolve`. Escape срабатывает только в полях ввода (`Escape` в обычном поле игнорируется, чтобы не терять ввод — флаг `inField`); в обычных модалках Escape — Отмена.

- **`openEditDialog`** (dblclick-rename блока): префилл — метка в D2-форме (`D2S.d2Escape`), сохранённое значение декодируется `D2P.decodeEscapes` — введённый `\n` значит перенос строки (не `\\n`). Применение: `render()` → `queueSave()` + `queueGen()`, новая метка — «последний шаг» через `D2HIST` (перед ним `applyGraph` текущего графа, чтобы история не «заряжала» изменения).
- **`confirmDialog`** (предупреждения): заголовок, текст, кнопки OK/Отмена.
- **`saveToBrowser`/`openFileListModal`** — см. «Файлы в браузере».

### Файлы в браузере (IndexedDB)

БД `d2editor` (`dbPromise`/`dbHandle`, store `files`, keyPath `name`, индекс `savedAt`). Хелперы: `dbFiles()` (упавшая БД → `Promise.reject`), `idbOp(db, mode, cb)` (обёртка над транзакцией, resolve/reject по событию, **не полагаться на `req.onsuccess` как функцию**), `fileList()` (записи `{name, savedAt, size}`, отсортированы по `savedAt`), `fileGet(name)`, `filePut(record)`, `fileDelete(name)`, `fileReset()` (удаление и пересоздание БД), `bytesText(n)` (русская склоняемая форма «N байт/КБ/МБ»).

`saveToBrowser()` — модалка «Сохранить файл в браузере»: фаза «ввод имени» (префилл `currentFile` или `"diagram"`, Enter = Сохранить; пустое имя → инлайн «Введите имя диаграммы», ввод остаётся). Ниже поля имени — **список сохранённых файлов** (тот же вид, что в открытии, но строки без кнопки «Открыть»; «Удалить» работает и ведёт через inline-подтверждение). Если `fileList()` уже содержит имя → фаза «перезапись» («…уже существует.» + Заменить/Отмена, Отмена возвращает ввод с сохранённым значением). Сообщения фаз идут в `#save-hint`, список при этом остаётся на экране; `renderSaveList` после `setContent` возвращает видимость `#modal-input`. Транзакция — через `filePut`, статус «Сохранено: имя», `currentFile = name`, `updateFileLabel()`. Если база падает уже при открытии окна (загрузка списка) — сразу фаза «база недоступна».

`openFileListModal()` — модалка «Файлы в браузере»: строки-кнопки `.file-row` (клик по телу — открыть, по «Удалить» — inline-подтверждение), строка хранилища (счётчик + объём; `navigator.storage.estimate()` с фолбэком `getSize()` — посчитать суммарный `size` записей). Открытие (`openStoredFile`): `fileGet` → `validateState` → `applyState` (граф, `lastGraphText`, позиции, viewport) → `D2HIST.clearHistory` → `updateUndoUI` → `saveState` → `currentFile` + `updateFileLabel` + статус «Открыт: имя».

**База недоступна** (`handleIdbDown`/`retryIdbDown`): открытие любой модалки файлов при падении `dbFiles()` — `onerror` с «Пересоздать базу файлов» (сохраняет имя в `#save-modal-input`, инлайн-сообщение в окне). `fileReset()` + повтор попытки. Обходные защитные ветки (`idbNotAvailable`) — «…недоступен в этом браузере».

### Экспорт и импорт файлов

Split-button «Копировать» (шеврон `#btnCopyMenu`) открывает меню `#copy-menu`:

- **Экспорт D2** (`exportStandardD2`): `D2S.toStandardD2(currentGraph(), outEl.value)` — единая точка приведения к стандарту (чистый сериализатор без маркеров) → нативный диалог `showSaveFilePicker` (фолбэк `Blob` + `a[download]`). Общий для файловых экспортов `downloadCode(content, ext, base)`: принудительное расширение `ext` (регэксп `/\.[^./\\]+$/` + `handle.move`), `suggestedName` = `base + "." + ext`, фильтр `application/x-d2` → `[".d2"]`, фолбэк `downloadBlob(content, "text/plain;charset=utf-8", suggested)`.
- **Экспорт файла** (`exportFile`/`exportDd2`): аннотированный `.dd2` — `D2S.serializeAnnotated(currentGraph(), {refText})`, расширение `.dd2`, имя из `exportName`.
- **Импорт D2** (`#import-file`, `.d2`/`.txt`/`.dd2`, `accept=".d2,.txt,.dd2"`): текст применяется через `applyCode` — без 3-секундного debounce, сразу `onTextEdit`.
- **Экспорт SVG** (`exportSVG`/`buildSVG`): самодостаточный векторный документ, генерируется прямо из графа (позиции `absPos`, размеры `boxSize`, рёбра `edgeGeometry` + `XYF.getSmoothStepPath`), без `foreignObject` и внешних ресурсов. Слои: фон контейнеров → фоны блоков → рёбра + подписи рёбер → подписи блоков (стрелки внутри групп не перекрываются заливкой).
- **В плане**: `export-drawio` (mxGraphModel XML), `export-mermaid`/`import-mermaid` — пункты меню-стабы со статусом «… — в разработке».

## 8. Упорядочение по стрелкам (`d2-sort.js`)

`sortByArrows(graph)` → новый граф с переставленными `order` (ноды) и `children` каждого контейнера; вход не мутирует.

- DFS pre-order **по скоупам**: верхний уровень — корни (без родителя); для каждого контейнера — его прямые дети.
- **Входящие стрелки считаются внутри текущего скоупа** (не глобально) — иначе рёбра между скоупами дают ложные «без входящих».
- Направление стрелки учитывается по семантическим концам (`edgeEndpoints`): для `<-` источник — `target`, цель — `source`; `--` ведёт себя как `->`.
- Для каждой исходящей стрелки (в порядке создания): цель — контейнер или блок внутри контейнера → в отложенный список; иначе → посетить цель.
- Порядок: блоки без входящих (в текущем порядке текста) → отложенные контейнеры/вложенные цели → непосещённый остаток.
- Циклы защищены множеством посещённых; порядок «примерно топологический»; детерминизм — от порядка рёбер.

## 9. Формы (`d2-shapes.js`) и анкоровка рёбер

- **Реестр** — каждая форма это запись `{ratio, params, render, outline}`. `params` — единственное место, где живут числа геометрии; `render` (SVG-пути) и `outline` (замкнутый полигон) строятся из одного `params`, поэтому анкоровка автоматически следует за геометрией. Fallback для отсутствующего/неизвестного имени — скруглённый прямоугольник (rx=8).
- **Модель**: поле ноды `shape` присутствует только при явном `shape:`, регистр сохраняется; `shape` на ребре и значения-массивы/блок-строки остаются в `rawAttrs` lossless. Сериализатор эмитит `shape:` сразу после `label`.
- **Размеры**: `circle`/`square` — 1:1 (`normalizeRatio` по максимуму w/h). Нормализация применяется в UI-пути: `boxSize` (index.html) и `nodeShapeBox` (анкоровка); `js/d2-layout.js` не трогает.
- **Анкоровка рёбер**: `edgeGeometry` (index.html) считает центр→центр обоих боксов и для не-контейнерных нод ищет точку выхода луча на полигоне `outlinePoints` формы через `outlineIntersect` (ближайшая точка; для вогнутых форм — первое пересечение). Контейнеры — прежняя прямоугольная рамка. `spPos`/`tpPos` (доминирующая ось) остаются эвристикой для `getSmoothStepPath`. Наконечники по `dir`: `->` = `marker-end` (`#arrow`), `<-` = `marker-start` (зеркальный `#arrow-start`), `<->` = оба, `--` = ни одного. Параллельные связи одной пары разводятся фан-аутом `EDGE_FANOUT = 21`: `parallelOffsets` группирует по **неупорядоченной** паре `(source, target)` (иначе `A -> B` и `B -> A` совпадали бы) и сдвигает луч каждого ребра на `(i-(n-1)/2)·21` по перпендикуляру к лучу (начальная точка сдвигается на `d·n`, анкера остаются точно на контуре). Знак смещения корректируется по текстовому порядку (`source < target`), т.к. нормаль в `edgeGeometry` зеркалится для обратной записи. Маркеры — `markerUnits="userSpaceOnUse"`, треугольник 24×12, остриё в начале координат; `refX = ∓6` — остриё выступает на `EDGE_INSET = 6` за конец пути, а `edgeGeometry` обрезает путь на те же 6px вдоль оси подхода (`inset` применяется только к концам с маркером: для `->` обрезается конец, для `<-` — начало, для `<->` — оба, для `--` — ни один). Остриё стоит точно на границе, толщина линии не портит его.
- **UI**: не-контейнерные ноды рендерятся инлайн-`<svg>` (`.nshape`) с путями `renderShape`; CSS-обвязка div (drag/выделение/group/src) остаётся — у `.node.shaped` рамка/фон прозрачные, состояния — box-shadow/outline + stroke пути. Селект форм `#shapeSel` всегда активен (как `#dirSel`): при выбранной не-контейнерной ноде смена значения применяет форму к ней (мутация графа → `render()` + `queueGen()`), при отсутствии выделения значение становится дефолтной формой новых блоков по «+ Блок» (`addBlock` копирует `shapeSel.value` в `shape` ноды; пустая опция — без формы). Метки `person`/`c4-person` — снизу (`shapeLabelBottom`, класс `.nlabel.bottom`).
- **Экспорт SVG**: `buildSVG` рисует фоны блоков той же `renderShape`, подписи person/c4-person — внизу.
